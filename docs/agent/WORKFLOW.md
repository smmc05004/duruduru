# 에이전트 공통 작업 절차

1. 관련 제품 문서, 기능 ID·수용 기준, 현재 코드와 테스트를 읽는다.
2. 목표, 파일 범위, 의존성, 위험, 검증 방법을 짧은 계획으로 제시한다.
3. 최신 `main`에서 목적이 하나인 작업 브랜치를 만든다.
4. 실패하는 테스트를 먼저 작성하고 최소 구현·리팩터링을 반복한다.
5. lint, 타입 검사, 관련 Jest 테스트, 필요한 Playwright 화면 점검을 실행한다.
6. 구현자와 분리된 reviewer agent가 명세·diff·검증 결과를 검토한다.
7. 확인된 지적을 반영하고, 재검토가 필요한 변경이면 다시 독립 검토한다.
8. 한글 커밋 메시지와 PR 체크리스트로 변경 목적·검증·남은 위험을 남긴다.

도구별 훅과 CI는 이 절차를 강제하거나 보조할 수 있지만, 절차 자체를 대체하지 않는다. 코드 변경이 없는 문서 작업에는 위험에 비례한 검증만 수행한다.

작업 단계와 근거는 `docs/agent/WORK_CYCLE.md`의 그래프와 `npm run cycle` 명령으로 추적한다.
