# 서비스 2차 고도화 계획

> 기준일: 2026-09-09. 사용자와 합의한 다음 고도화 방향이다. 현재는 계획 수립 단계이며 구현 완료나 구현 착수 지시를 뜻하지 않는다. MVP 2단계 및 서비스 1차 고도화와 구분한다.

## 목표와 범위

사용 가능한 시간으로 목적지를 먼저 추천하는 경험을 유지하면서, 현지 이동에 필요한 시간을 일정에 확보하고 출발 지역 선택을 확장한다. 자차·다음날 귀가하는 1박 2일·관광 07:00~21:00·출발과 귀가 이동 시각 무제한이라는 기존 조건을 유지한다.

- 관광지·음식점 간 이동은 보유 좌표의 직선거리로 일반 예상시간을 산출한다.
- 출발지는 표준 지역 목록에서 검색·선택하며, 선택 지역의 KTDB 일반 예상시간으로 후보와 일정을 재계산한다.
- 거리 계산과 출발 지역 선택에 새 유료 API, 외부 경로 API, 별도 OSRM 서버, 주소 검색·지오코딩 API를 요구하지 않는다. 기존 TourAPI 음식점·상세 조회는 유지한다.
- 실제 도로 거리, 실시간 교통, 집 주소부터의 정밀 이동시간을 제공하는 범위는 아니다.

## 1. 장소 간 직선거리 기반 이동시간

### 구현 기본 정책 — 2026-09-09 총괄 결정

`straight-line-v1`은 공공기관의 운전시간 관측값이 아닌 제품 추정 규칙이다. 평균 30km/h로 환산해 5분 단위로 올림하며 최소 5분을 확보한다. 동일한 유효 좌표는 0분이다. 결측·잘못된 좌표는 미확정으로 구분하고 같은 날짜의 연속 장소 사이에 15분을 임시 확보한다. 이 예약 시간을 계산된 예상시간이라고 표시하지 않는다.

연결 이동은 기존 활동 사이 15분 여유를 대체하며, 활동하는 날의 순수 자유시간 30분은 따로 유지한다. 관광·개인 일정·현지 식사의 실제 연속 순서를 연결하고, 지역 대표점과 첫/마지막 장소는 자동 연결하지 않고 미확정 안내로 둔다. 야간 현지 활동은 배치하지 않으며 숙소를 경유했다고 가정하지 않는다.

초기 관광 초안은 기존 최소 3곳 범위에서 배치 가능한 수를 검토한다. 음식점 배정 뒤 시간이 부족하면 이미 받은 다음 후보를 검토하되 관광을 자동 삭제하지 않는다. 모두 불가하면 식사 블록·미확정 이동 예약과 사유를 유지한다. 사용자 교체 실패는 기존 계획 전체를 보존한다.

기존 저장본은 이동 미반영 기준선으로 복원하고 자동 재배치하지 않는다. 새 검색 또는 명시적 편집 성공부터 새 이동 버전을 적용하며 실패 시 원본을 유지한다. 새 버전은 이동 상태·원천·연결을 저장한다.

출발 목록은 검증된 KTDB 매핑 항목을 노출한다. 일반구가 있는 도시는 구 선택을 필수로 하고 세종은 단일 항목으로 둔다. 별칭은 데이터에 명시한다. 출발 변경은 새 검색 제출 시에만 적용하며 취소·실패는 기존 상태, 성공은 새 검색 결과를 표시하고 기존 저장본을 보존한다.

아래의 ‘구현 전 구체화’ 목록 중 위 정책으로 해소된 항목은 재질문하지 않는다. 남은 기술 선택은 이 범위 안에서 근거와 검증 결과를 작업 계획에 기록한다.

### 사용자 경험

관광지→관광지, 관광지→음식점, 음식점→다음 관광지 사이에 예상 이동시간을 표시하고 실제 일정 시간을 확보한다. 관광·식사·이동을 배치하고 남은 시간을 자유시간으로 표시한다. 기존 활동 사이 여유와 이동시간을 중복 차감하지 않는다.

계획 상단 또는 하단의 기본 노출 영역에 다음 주의사항을 표시한다. 데이터 근거 펼치기 안에만 숨기지 않는다.

> 장소 간 이동시간은 직선거리를 기준으로 추정했어요. 실제 도로의 우회, 교통 상황, 주차 등에 따라 달라질 수 있어요.

이 문구는 현지 장소 간 추정에 해당한다. 출발 지역↔목적지의 KTDB 시간과 계산 원천을 혼동하지 않게 한다.

### 계산과 일정 정합성

- TourAPI 관광지·음식점의 유효한 위도·경도로 직선거리를 계산하고, 명시된 시간 환산 규칙으로 예상시간을 산출한다.
- 직선거리는 계산값, 이동시간은 정책 기반 추정값으로 구분한다. 앞선 대화의 거리별 분 수·지역 유형별 배율은 확정 수치가 아니다.
- 최초 초안, 음식점 배정·교체, 관광지 교체·추가·삭제·순서·날짜·체류시간 변경에서 관련 이동 구간을 재계산한다.
- 관광·식사·사용자가 고정한 시각·귀가 마감과 충돌하지 않게 배치한다. 자동 초안의 장소 수 조정과 사용자 편집 실패 시 이전 계획 보존 기준을 상세 기획으로 정의한다.
- 검색 단계에는 음식점 좌표가 아직 없으므로 식당 선택 전 초안과 선택 후 재계산의 차이를 명시한다. 알 수 없는 구간을 0분으로 확정하지 않는다.
- 좌표 결측, 미선택 식당, 좌표 없는 개인 일정·숙소의 구간은 계산 불가 상태로 구분한다. 밤사이 두 관광지를 숙소 경유가 확인된 경로처럼 연결하지 않는다.
- 저장·불러오기에서도 이동시간과 일정의 일관성을 유지한다. 기존 저장본의 이관·재계산은 버전 정책으로 정의한다.

### 구현 전 구체화할 사항

기준 속도 또는 거리 구간별 시간, 최소시간·반올림, 기존 여유시간과의 관계, 계산 불가 구간의 시간 확보 방법을 정한다. 검증하지 않은 도시·군·산악 보정값을 사실처럼 적용하지 않는다. 지역 도착·귀가 대표점과 첫·마지막 방문 장소의 연결 범위도 명시해 KTDB 시간과 중복 계산하지 않는다.

## 2. 출발 지역 검색·선택과 KTDB 재계산

### 사용자 경험

`출발 지역 검색`에서 `강남`, `수원`, `해운대` 등을 입력하면 앱에 포함한 표준 지역 목록을 제시한다. 사용자는 제시된 항목을 선택하며 자유 입력 문자열 자체를 출발 지역으로 저장하지 않는다. 전체 시도·시군구 명칭으로 동명 지역을 구분하고, 검색 없이 찾을 수 있는 계층형 선택도 제공한다.

- 특별시·광역시는 필요한 구·군을 선택한다.
- 도 지역은 시·군을 선택하고 KTDB가 일반구를 구분하는 도시는 구까지 식별한다.
- 세종처럼 하위 시·군·구가 없는 구조는 불필요한 선택을 요구하지 않는다.
- 상세 집 주소·읍·면·리·건물 주소를 요구하지 않는다. 결과는 선택 지역의 대표점 기준임을 안내한다.

### 데이터와 계산

- 현재 KTDB 2024의 252개 존 간 산출물을 활용한다. UI용 지역명과 내부 KTDB ID를 분리하고 검증된 매핑으로 연결한다.
- 출발 지역 변경 시 시간 적합 후보, 출발 권역 제외, 목적지 비교 지표, 도착·귀가 출발 시각과 일정을 다시 계산한다.
- 같은 광역시의 여러 구 등 출발 권역 제외 정책은 기존 목적지 그룹 기준을 유지한다.
- 전국 선택 UI를 제공할 수 있다는 것과 모든 지역에서 추천 가능하다는 것은 구분한다. 행정구역 변경·매핑 누락·KTDB 경로 결측을 확인해 지원 목록을 만든다.
- 제주·울릉 등 육지와 자동차 시간값이 연결되지 않은 쌍을 임의 값으로 채우지 않는다. 지원 불가 지역 또는 목적지 쌍에는 이유를 표시한다.
- 기존 서울·부산 저장 계획의 출발 의미를 보존하며 새 출발 지역 ID 계약으로 이관한다.

### 구현 전 구체화할 사항

KTDB 존과 UI 지역 목록을 대조해 지원·미지원·검토 필요 목록을 만든다. 일반구가 나뉜 시의 상위 시 선택 처리, 변경 행정명 검색 별칭, 기존 계획을 보유한 상태에서 출발지를 변경할 때의 재검색·사용자 편집 보존 경계를 상세 기획으로 정의한다.

## 진행 순서와 완료 판단

1. 두 기능의 상세 기획과 위 미정 규칙을 확정한다. 이 문서의 미정 사항을 구현자가 임의 상수로 확정하지 않는다.
2. 장소 간 이동시간과 공통 일정 재계산을 구현한다. 음식점 선택 전후·교체·시각 고정·좌표 결측·저장 복원을 함께 검증한다.
3. 출발 지역 목록·매핑을 검증하고 검색 UI와 KTDB 재계산을 구현한다. 서울·부산 외 지원 지역, 동명 지역, 일반구, 세종, 미지원 경로를 검증한다.

두 기능 모두 기술적으로 구현 가능하다. 1번은 시간 환산·예외 정책, 2번은 지원 지역 매핑 점검이 선행 준비다. 추가 API 키나 자체 경로 서버 준비는 필요하지 않다. MVP 검증 생략 규칙은 적용하지 않으며 고도화 단계에 맞는 도메인·화면 검증을 작업 계획에 포함한다.

## 문서 적용 경계

이 문서는 다음 구현 방향의 기준이다. 현재 코드와 1차 고도화 문서의 `현지 이동시간 미계산`, `서울·부산 출발`은 기존 구현 기준선으로 남는다. 상세 기획 확정 시 PRD·추천·거리·API 흐름·저장 정책의 해당 부분을 일관되게 갱신한다. 정확한 출발 주소 좌표 보정, 도로 경로 계산, 여행 기간 확대는 이번 범위에서 제외한다.
