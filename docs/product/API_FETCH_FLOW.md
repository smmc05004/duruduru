# MVP 데이터 조회 흐름

## 목적

MVP는 모든 지원 지역의 모든 데이터를 한 번에 조회하지 않는다. 먼저 이동시간과 관광지로 1차 후보를 좁힌 뒤, 그 후보 지역에만 음식점 정보를 연결한다. 사용자가 후보를 선택할 때는 이미 관광지·식당 데이터가 연결돼 있어야 한다.

TourAPI는 서버가 `TOUR_API_SERVICE_KEY`로 호출한다. 브라우저에는 서비스 키나 원시 응답을 전달하지 않는다.

## 1단계: 관광지 기반 1차 후보 검색

사용자가 `갈 수 있는 곳 찾기`를 누르면 서버가 다음만 조회·계산한다.

1. 입력한 출발지와 지원 여행지의 시·군·구 청사 대표점 간 일반 예상 이동시간
2. 지원 여행지별 최신 관광지 데이터와 관심사 분류
3. 왕복 이동시간, 휴식 시간, 관광지 1시간 체류 규칙으로 만들 수 있는 관광 계획의 수

왕복 후 남는 시간에 관심사 관광지를 여러 곳 배치할 수 있는 지역만 **1차 후보**로 남긴다. 이 단계에서는 음식점·대표음식 정보를 아직 조회하지 않는다.

1차 후보의 관광지 데이터와 청사 간 일반 예상 이동시간은 검색 스냅샷에 보존한다.

## 2단계: 1차 후보의 음식점 연결

같은 검색 요청 안에서 서버는 **1차 후보 지역에 대해서만** 다음 최신 데이터를 조회한다.

1. TourAPI 음식점과 상세 운영·휴무 정보
2. 지역 대표음식 근거와 공식 지정 여부를 확인하는 공공데이터

서버는 대표음식을 취급하고 식사 시간에 운영 가능한 음식점만 남긴다. 후보가 여럿이면 공식 지정 여부, 해당 식사와 연결된 관광지까지의 직선거리, 장소 ID 순으로 하나를 고른다. 직선거리는 음식점 선택의 동점 해소 기준일 뿐 이동시간·일정 제약·화면 표시에는 쓰지 않는다.

점심·저녁을 모두 배치할 수 있는 지역만 최종 추천 후보로 남긴다. 최종 후보에는 관광지·음식점 데이터와 선정 근거가 모두 연결돼 있으며, 이를 검색 스냅샷에 함께 보존한다.

## 3단계: 목적지 선택과 계획 생성

사용자가 최종 후보 중 한 지역을 선택하면 새 외부 API를 호출하지 않는다. 연결된 검색 스냅샷으로 점심·저녁과 관광지를 포함한 1박 2일 참고 계획을 만든다. 관광지·음식점은 각각 1시간이며, 여행지 내부 이동시간은 계산하지 않는다.

## 실패 처리

- 1단계 관광지 조회 또는 청사 간 일반 예상시간이 없으면 해당 지역을 1차 후보에서 제외한다.
- 2단계에서 점심 또는 저녁에 배치할 음식점을 찾지 못하면 해당 지역을 최종 추천 후보에서 제외한다.
- API 장애와 정상 응답이지만 조건을 충족하는 데이터가 없는 경우를 구분한다.
- 정적 PoC 데이터, 임의 이동시간, 빈 음식점 fallback으로 대체하지 않는다.
