## 목적과 범위

MVP 1단계의 검색→지역 선택→관광·식사 결과를 유지하며 비교하고 일부를 수정해 여행 준비에 사용할 수 있는 참고 초안을 만든다. 서울·부산 출발, 자차, 다음날 복귀하는 1박 2일, 기존 TourAPI 관심사 입력을 유지하고 필수 입력을 늘리지 않는다.

예약·내비게이션·실시간 교통·영업 보증·숙소 추천·LLM·평점·리뷰·계정·기기 간 동기화·공개 공유는 제외한다. 출발지 추가, 축제·날씨는 후속이다.

## 데이터와 정직성

- 기존 KTDB 2024 시간표, TourAPI 지역 프로필, 지역N문화 음식 키워드, 모범음식점 보조 캐시를 재사용한다. 같은 편도 값을 양방향에 사용한다.
- 추가 외부 호출은 기존 서버 전용 키를 사용하는 무료 TourAPI 목록·상세로 제한한다. 무료는 무제한이 아니다. 공식 안내: https://www.data.go.kr/tcs/dss/selectApiDataDetailView.do?publicDataPk=15101578 . 이미지별 이용 조건을 지킨다.
- 직선거리는 근접성의 보조 기준이며 도로 거리·실제 동선·시간으로 환산하지 않는다. 좌표 결측은 근접성 가점만 생략한다.
- 아래 방문시간·여유시간·정렬·거리 문턱은 **제품 휴리스틱**이지 공공기관 보증값이 아니다. KTDB 기준연도, 프로필 생성일, 목록 조회일과 구분해 설명한다.
- 상세 운영정보 결측은 계획 실패 사유가 아니다. 원문을 정리해 보여주고 방문 전 확인을 안내하며 모든 운영 문장을 자동 해석하지 않는다.

## P2-01 — 공통 시간 엔진

### 입력·출력

입력은 검증된 출발·복귀 일시(Asia/Seoul), 편도 분, 선택 관광지·방문 분, 편집 의도다. 날짜 차이는 정확히 1일이며 출발·복귀 시각에는 제한이 없다. 출발지와 여행지 양쪽에서 22시 출발도 가능하다. 지원 출발지·자차·알려진 관심사 1개 이상을 서버에서 검증한다. 잘못된 JSON·타입·날짜는 요청 오류이지 API 장애가 아니다.

출력 블록은 안정적 ID, 날짜, 시작·종료 시각, 종류(지역 간 이동/관광/현지 식사/이동 중 자유 식사/자유시간/휴식), 장소 콘텐츠 ID, 방문 분, 고정 여부, 근거를 가진다. 상호·장소명으로 식별하지 않는다. 복귀 시각은 귀가 완료 시각이지 귀가 출발 시각이 아니다.

### 결정 규칙

1. 관광·현지 자유활동은 07:00~~21:00에만 배치한다. 지역 간 이동은 야간·자정 통과를 허용하며 양방향에 KTDB 편도 운전 분을 각각 정확히 확보한다. 야간 휴식은 현지 도착 이후~~귀가 출발 이전의 야간 구간에만 넣고 이동과 겹치지 않는다. 여행지 내부 이동 블록은 만들지 않는다.
2. 점심 11:30~~13:30, 저녁 17:30~~19:30 중 출발~복귀 범위 안에 60분 식사 시작 후보가 있는 끼니만 반드시 배치한다. 여행 범위 밖 식사는 생성하지 않으며 네 끼를 강제하지 않는다. 예를 들어 22시 출발이면 첫날 점심·저녁 없이 다음날 식사만 배치한다.
3. 식사 시작 후보는 점심 11:30/12:00/12:30, 저녁 17:30/18:00/18:30이다. 유한한 조합에서 유효 배치를 결정하며 같은 입력은 같은 결과여야 한다.
4. 출발 이동은 사용자 출발에서 앞으로, 귀가 이동은 사용자 복귀에서 뒤로 운전 분을 확보한다. 식사와 겹치면 운전을 중단한 `이동 중 자유 식사` 60분을 별도 확보한다. 식사 분은 운전 분을 대체하지 않는다. 휴게소·경유지·식당을 임의로 만들지 않는다.
5. 도착 후~귀가 출발 전에 완전히 들어가는 식사는 현지 식사다. 이동 중 자유 식사는 식당 배정 대상 밖이다. 음식점 목록이 없어도 식사 블록은 유지한다.
6. 기본 관광은 60분씩 총 3~6개, 하루 최대 3개다. 관광 가능한 날에 배치하며 야간 출발·이른 귀가로 관광할 수 없는 날은 관광을 강제하지 않는다. 식사 사이에 방문을 잘라 넣지 않는다. 관광하는 날은 현지 자유시간 최소 30분을 남기고 그 외 낮의 남는 시간도 자유시간이다.
7. 여러 시간 배치가 가능하면 배치 관광 개수 많은 것 → 현지 식사 많은 것 → 식사 시작이 이른 것 순이다. 관광 선택 순서는 P2-03이다. 후보 판정·결과·편집은 같은 엔진을 사용한다.

### 예외·수용 기준

- 08:00 출발·편도 270분에 11:30부터 이동 중 점심 60분이면 도착은 13:30이다. 도착 전 현지 식사·관광을 표시하지 않는다.
- 다음날 20:00 복귀·편도 270분에 귀가 중 저녁 60분이면 귀가 운전 시작은 늦어도 14:30이다. 여행지 17:30 저녁과 20:00 귀가를 동시에 표시하지 않는다.
- 운전·여행 범위 내 식사·낮의 최소 관광·여유가 공존하지 않으면 시간 조건 불가와 구체적 부족 이유를 제공한다. 야간 출발 자체는 입력 오류가 아니다. 임의 시간·중복 장소로 메우지 않는다.
- 22시 출발 후 새벽 현지 도착이면 도착~~07시는 휴식하고 다음날 관광한다. 여행지에서 22시 귀가 출발이면 21~~22시는 현지 휴식하고 이후 이동한다. 귀가 완료는 입력한 다음날 날짜 안이어야 한다.
- 현지 활동 가능시간은 도착~귀가 출발 사이에서 휴식을 제외한 구간 합이다. 현지 식사·관광·자유시간을 나누며 36시간을 관광 가능시간으로 표시하지 않는다.
- 사용자가 삭제한 편집본은 관광 최소 개수의 예외다. 식사·운전·휴식 경계는 편집 후에도 유지한다.

## P2-02 — 지역 그룹과 초안 기반 추천

1. 매핑·양수 이동시간이 있는 지역만 사용한다. 특별시·광역시·특별자치시는 시도 하나, 도 지역은 시·군 하나로 묶고 일반구는 상위 시에 합친다. 읍·면·리 후보를 만들지 않는다. 출발지와 동일한 최종 그룹은 모든 내부 구를 포함해 제외한다.
2. 그룹 관광지를 콘텐츠 ID로 합친다. KTDB 대표 존은 출발지 기준 일반 예상시간이 가장 짧은 존(동점 존 ID)이다. 실제 장소 주소까지의 시간이 아님을 근거에 보존한다. 음식점 조회 지역은 이 대표 존에 고정하지 않는다.
3. 선택 관심사의 공식 분류 관광지가 3개 이상인 그룹에서 P2-03·P2-01로 실제 초안을 만든다. 음식점 존재·운영시간은 후보 조건이 아니다. 초안 불가 그룹은 제외한다.
4. 정렬: 초안의 선택 관심사 충족 비율 높은 순 → 배치 관광 개수 많은 순(최대 6) → 세부 분류 종류 많은 순 → 하루 내 연속 장소의 유효 직선거리 평균 짧은 순 → 왕복 예상시간 짧은 순 → 그룹 ID. 거리 쌍이 없으면 근접성 최하위이며 후보 제외는 아니다. 원천 관광지 총개수로 정렬하지 않는다.
5. 결과는 최대 3개다. 가능한 곳이 1~2개면 그대로 제시하고 0개면 시간/분류 부족을 설명한다. 세 곳을 채우기 위해 규칙을 완화하지 않는다.

카드는 초안 방문 장소·방문 수·실제 충족 관심사·왕복 예상시간·현지 활동 가능시간·자유시간·추천 이유를 보여준다. 미충족 관심사를 충족했다고 표시하지 않는다.

수용 기준: 서울 출발에 서울 내부 구가 없고 수원 일반구는 한 후보다. 동일 입력·스냅샷은 같은 순서다. 음식점 실패가 후보를 취소하지 않는다.

## P2-03 — 관광 장소 선정

- 공식 분류는 자연 A01, 역사 A0201, 휴양 A0202, 문화 A0206 또는 유형 14, 레저 A03 또는 유형 28이다. 세부 다양성은 cat3 → cat2 → 공식 관심사 순으로 사용 가능한 값을 쓴다.
- 첫 장소는 미충족 선택 관심사 포함 → 세부 분류 희소성 → 콘텐츠 ID 순이다. 이후에는 미충족 관심사 → 당일 미사용 세부 분류 → 직전 장소와 가까운 순 → 콘텐츠 ID로 결정한다. 다음날에는 새 묶음을 시작할 수 있다. 결측 좌표는 근접성 가점만 생략한다.
- 한 콘텐츠 ID는 여행 전체 한 번이다. 원천 3개라면 네 번째에 첫 번째를 반복하지 않고 자유시간을 둔다.
- 정규화 이름·정규화 주소 일치, 좌표 100m 이내가 모두 성립하는 중복 레코드는 대표 하나를 우선한다. 하나라도 부족하면 삭제·병합하지 않는다.
- 공통 장소명이 있고 주소가 같으며 300m 이내인 세부 지점은 같은 날 연속 배치를 피하는 약한 감점이다. 가까운 것만으로 유적지 전체를 병합하지 않는다. 해당 감점은 미충족 관심사 우선 다음, 세부 분류 우선 전에 적용한다.
- 사용자 근거는 ‘주변 장소를 함께 구성’이며 도보 가능·차량 몇 분이라고 주장하지 않는다.

수용 기준: ID 반복 없음, 좌표 결측으로 전체 실패 없음, 세부 지점 의심만으로 원천 레코드 삭제 없음.

## P2-04 — 관광 일정 주변 음식점

목적지 선택 후에만 조회한다. 실제 초안 관광지가 속한 매핑 지역을 방문 수 내림차순 → 첫 방문 순 → 지역 ID 순으로 최대 3개 고른다. 지역당 100개씩 최대 3페이지, 동시성 최대 2, 목록 작업 최대 9호출이다. 상한 도달 시 조회 범위가 제한됨을 근거에 남긴다. 관광지역이 없으면 선택 그룹의 매핑 지역을 같은 상한으로 사용한다.

식사 앞뒤 관광지(없으면 당일 첫 관광지)를 기준으로 거리 합 짧은 순 → 지역N문화 키워드 → 안전하게 연결한 모범음식점 근거 → 콘텐츠 ID 순이다. 앞뒤 중 하나뿐이면 그 거리만 쓴다. 좌표 결측은 근접성 최하위다. 도로 동선 최적화·맛집 순위로 표현하지 않는다.

현지 식사 전체에서 콘텐츠 ID를 중복 배정하지 않는다. 교체 후보도 다른 식사 사용 ID를 제외한다. 부족한 칸은 60분을 유지하고 `추천할 식당을 더 찾지 못했어요`로 표시한다. 이동 중 자유 식사는 결측이 아니라 추천 대상 밖이다.

지역N문화 2023 자료는 향토음식 키워드 보조 원천이며 관련 음식점 필드는 직접 추천하지 않는다. 모범음식점은 전화번호 정확 일치 또는 전화번호 없을 때 정규화 상호·주소 동시 일치만 결합한다. 보조 캐시 실패는 가점만 생략한다.

일부 지역 실패는 성공 목록과 관광을 유지하고 부분 실패·재시도를 표시한다. 전부 실패해도 관광·시간 블록은 유지한다. 재시도·이전 목적지 늦은 응답이 현재 계획을 덮어쓰지 않는다. 음식점 상세는 클릭한 콘텐츠 ID 기준이며 일정 재생성을 유발하지 않는다.

## P2-05 — 부분 편집

입력은 계획 스냅샷과 한 편집 명령이다. 관광 고정/해제·교체·방문시간 30/60/90/120분 변경·삭제, 현지 식당 교체를 제공한다. 직접 시작시각 지정·날짜 강제 이동·식사시간 수정은 제외한다.

- 고정은 **장소 선택 보존**이며 시각·날짜 고정이 아니다. 자동 교체·삭제하지 않는다. 방문시간 수정은 허용한다. 직접 교체·삭제 전 고정을 해제하도록 안내한다.
- 교체는 같은 그룹의 선택 관심사에 맞는 미사용 관광지 대체 목록에서 선택한다. 기존 방문시간을 유지한다.
- 삭제는 해당 시간을 자유시간으로 전환하고 다른 관광지를 자동 추가하지 않는다. 불가 편집을 성립시키기 위해 다른 장소를 몰래 삭제하지 않는다.
- 시간 수정·관광 교체는 유지할 장소 목록으로 공통 엔진을 재계산한다. 경계를 충족하지 못하면 **편집 전 계획 유지**와 원인을 표시한다. 성공한 변경만 원자적으로 반영한다.
- 식당 교체는 해당 현지 식사만 바꾼다. 관광·다른 식당·시간표·후보 순서는 유지한다. 대체 후보 없으면 기존 식당을 유지한다.
- 관광 수정 후 사용자가 고른 식당은 유지한다. 새로운 음식점 조회가 필요하면 별도 재시도로 처리하고 관광 편집을 실패시키지 않는다.
- 저장 후 편집 시 ‘저장 후 변경됨’을 표시한다. 새 검색·다른 목적지는 새 초안이다. 요청을 검색/목적지/콘텐츠 ID로 구분해 오래된 응답을 무시한다.

수용 기준: 한 칸 교체가 전체 초기화하지 않음, 불가 편집 이전상태 보존, 동명 식당 ID별 상세 정확, 삭제 관광 자동 부활 없음.

## P2-06 — 이 기기 저장

최대 10개 계획을 명시적 저장 버튼으로 브라우저에 보존한다. ID·스키마 버전·저장/수정일·입력·목적지/대표존·데이터 기준·관광/식당 기본 스냅샷·시간 블록·고정/편집 상태를 저장한다. API 키·원시 응답·전국 프로필·상세 HTML은 저장하지 않는다.

불러오기는 저장 당시 계획을 복원하고 자동 재검색·식당 재배정하지 않는다. ‘저장 당시 정보’와 날짜를 표시하며 상세 클릭은 새 조회할 수 있다. 삭제는 선택 계획만 확인 후 지운다. 10개 초과 시 삭제를 안내하며 몰래 덮어쓰지 않는다.

저장소 차단·용량 부족·깨진 JSON·미지원 버전은 앱을 중단하지 않고 안내한다. 저장 실패를 성공으로 표시하지 않는다. 불러오기 시 날짜·ID·블록 범위·타입을 검증하고 잘못된 저장본은 적용하지 않는다. 서버 저장·로그인·기기 간 동기화는 없다.

## P2-07 — 관광지 클릭 상세

클릭 시에만 서버가 콘텐츠 ID·지원 콘텐츠 유형으로 공통/소개 상세를 조회한다. 제목·주소·소개·대표 사진·제공되는 이용시간·휴무·요금·연락처를 정규화한다. 한 번 열 때 최대 2호출, 동시성 최대 2다. 별도 이미지 목록 일괄 수집은 제외한다.

HTML·개행·빈 값을 안전한 표시용 텍스트로 정규화하고 외부 HTML을 실행하지 않는다. 사진은 이용 조건을 확인한 기존 목록 또는 상세 사진만 쓴다. 사용권 불확실 시 사진 없이 표시한다.

부분 성공은 있는 정보를 표시하고 결측은 ‘제공 정보 없음/방문 전 확인’이다. 실패는 시트 안 재시도다. A 닫기→B 열기 후 A 응답이 B를 덮어쓰지 않는다. 상세 결과로 후보·일정·저장본을 몰래 재배치하지 않는다.

## 화면 디자인 기준

확정 디자인은 [H · 여행 수첩](../design/DESIGN_DIRECTION.md)이며 [디자인 토큰](../design/DESIGN_TOKENS.md)과 `design/screens/`의 Input·Main·Itinerary·RestaurantDetail 및 예외 상태 시안을 기준으로 구현한다. MVP 2단계 기능 추가가 새 디자인 방향 도입을 의미하지 않는다.

- 기존 모바일 중심 화면 폭·정보 밀도·종이 바탕·잉크 테두리·하드 섀도·서체 역할을 유지한다. 출발지는 서울/부산 세그먼티드, 관심사는 머스터드 선택 칩을 사용한다.
- 조건 입력 → 추천 목록 → 선택한 여행 일정의 단계가 구분되도록 구성한다. 목적지 카드는 지명·시간 비율·설명·관심사를 우선 표시한다. 최대 3곳 규칙과 실제 활동시간 설명은 이 기획이 우선한다.
- 일정은 기존 시간 열과 세로 레일, 종류별 카드로 표시한다. 관광지·식당 교체 및 고정·삭제·방문시간 변경은 해당 항목의 보조 동작으로 제공해 일정 읽기를 방해하지 않는다. 새 편집·저장 UI는 기존 버튼·필드·카드 토큰을 재사용한다.
- 관광지·음식점 상세는 기존 상세 시트 표현을 공유한다. 오류·결과 없음·식사 부분 실패는 기존 디자인의 상태 구분을 유지한다.
- 내부 분류 코드·수집 기록·계산 근거는 기본 일정의 주정보로 늘어놓지 않고 펼쳐보기로 제공한다. 일반 예상시간과 방문 전 확인 안내는 간결하게 유지한다.
- 시안의 과거 기능·시간 예시와 최신 정책이 충돌하면 최신 제품 규칙을 적용한다. 디자인 복원을 위해 야간 이동·부분 편집·저장·상세·재시도 기능을 제거하지 않는다.

## 인계·완료 판단

수용 기준은 구현·사용자 확인 기준이지 이번 작업에서 테스트를 실행하라는 뜻이 아니다. employee는 시간 엔진 → 지역/관광 초안 → 음식점 → 편집/저장 → 관광 상세/통합 순으로 계획하고 구현한다. 기존 서비스 정의·디자인·에이전트 하네스는 유지한다. 최종 PR은 기능 ID, 제한, 미실행 검증, 외부 데이터 결측과 호출 상한을 사실대로 기록한다.
