# DURUDURU MVP 제품 요구사항

> MVP 2단계는 완료된 구현 기준선이다. 다음 승인 범위는 [서비스 고도화 계획](SERVICE_ENHANCEMENT_PLAN.md)의 1~4번이며 기능·알고리즘·예외·수용 기준은 [고도화 기획서](SERVICE_ENHANCEMENT_SPEC.md)를 따른다. 고도화 기획은 단계별 구현 예정이지 구현 완료 상태가 아니다. 교체하지 않는 시간·음식·데이터 정책은 [MVP 2단계 기획서](MVP_PHASE_2.md)를 유지한다.

## 제품 정의

DURUDURU(두루두루)는 목적지를 먼저 정하지 않는 국내 여행 플래너다. 사용자가 출발지와 출발·복귀 가능 시간을 입력하면, 그 시간 안에 현실적으로 다녀올 수 있는 목적지를 먼저 추천하고 선택한 지역의 일정까지 생성한다.

기존의 “경주에 갈 건데 무엇을 하지?”가 아니라, “이번 주말 이 시간 안에 어디를 다녀올 수 있지?”를 해결한다.

## 문제와 대상 사용자

짧은 주말이나 연휴에 여행할 시간은 있지만 목적지를 정하지 못해 계획을 시작하지 못하는 사람이 대상이다.

MVP의 우선 대상은 **1박 2일 국내여행만** 계획하는 자차 여행자다. 당일치기·2박 이상은 입력·추천 범위에서 제외한다. 관심사는 TourAPI 공식 분류 근거가 있는 자연·역사·휴양·문화·레저만 지원한다. MVP 출발지는 서울특별시(KTDB 서울 중구 존 대표 지역권)와 부산광역시(KTDB 부산 중구 존 대표 지역권)를 지원하며, 경주·공주·강릉은 초기 예시·검증 지역일 뿐 목적지 후보 범위는 KTDB 2024의 전국 252개 지역권이다.

## 핵심 가치

- 가용시간 안에 가능한 목적지를 먼저 제안한다.
- 선택한 지역을 어떻게 둘러볼지 판단할 수 있는 **실행 가능한 참고용 여행 계획**을 만든다. 이는 예약·내비게이션·분 단위 실행을 보증하는 일정표가 아니다. 후보 검색은 정기 수집한 관광지 지역 프로필과 국가교통DB 기반 지역 간 자동차 일반 예상 이동시간으로 목적지를 고른다. 사용자가 목적지를 선택한 뒤 **선택 권역 안에서 실제 관광지가 있는 하위 지역**의 TourAPI 음식점 목록을 제한 조회해 현지 식사를 채운다. 음식점 운영시간·메뉴·상세 정보는 사용자가 음식점을 열어 볼 때 조회한다. 실시간 교통·도로 길찾기·내비게이션은 제공하지 않으며 방문 전 최신 운영 정보 확인은 여전히 필요하다.
- 추천 이유와 시간 계산의 근거를 보여 사용자가 결과를 납득할 수 있게 한다.

## MVP 사용자 여정

1. 사용자가 검증된 표준 출발 지역을 검색·선택하고 출발·복귀 일시, 자차 여부, 관심사를 입력한다. 일반구가 있는 도시는 구까지 선택하고 관심사는 1개 이상 선택한다. 서울/부산 빠른 선택은 기존 중구 대표점을 유지한다.
2. 시스템이 1일차와 2일차를 걸치는 1박 2일 입력만 받는다. 선택 출발 지역권에서 전국 252개 여행 지역권까지의 왕복 이동시간으로 후보를 먼저 걸러낸 뒤, 서울·부산 등 광역시는 시도 단위로, 도 지역은 시·군 단위로 후보를 묶는다. 정기 수집한 TourAPI 지역 프로필 인덱스에서 선택 관심사의 공식 분류 관광지가 **서로 다른 콘텐츠 ID 기준 3개 이상**인지를 평가한다. 이 단계에서는 음식점 API를 호출하지 않는다.
3. 관광·식사·휴식·여유시간이 실제 배치되는 초안을 기준으로 최대 3개 목적지와 방문 장소, 관심사 충족, 왕복 예상시간, 현지 활동 가능시간을 제시한다. 출발 권역은 제외하며 도 지역 일반구는 상위 시로 합친다.
4. 사용자가 한 목적지를 선택한다.
5. 목적지를 선택하면 실제 관광 장소가 속한 하위 지역의 TourAPI 음식점 목록을 제한 조회한다. 관광 기본 방문은 1시간이며 30/60/90/120분으로 수정 가능하다. 점심·저녁은 각각 1시간 확보하되 현지 또는 이동 중 자유 식사로 배치하고 운전과 중복 계산하지 않는다. 현지 식사에는 서로 다른 음식점을 배정하고 부족하면 안내를 남긴다. 현지 연속 장소는 직선거리 기반 예상 이동시간을 확보하고, 식당/관광 변경 후 다시 계산한다. 결측은 미확정 예약으로 표시하며 계획 기본 영역에 추정 주의사항을 노출한다. 운영정보는 장소 클릭 상세로 확인한다.
6. 사용자는 관광지·식당을 교체하고 관광지를 고정·삭제하거나 방문시간을 변경할 수 있다. 변경 불가 시 기존 계획과 이유를 보존한다. 이 기기에 계획을 저장·불러오고 관광지·음식점 상세에서 제공되는 운영정보를 확인한다.

상세 정책은 P2-01~P2-07을 따른다. 기준 시나리오는 1일차 08:00 출발·2일차 20:00 복귀다.

출발·귀가 시각은 제한하지 않는다. 출발지와 여행지에서 22시 출발도 가능하며, 21:00~07:00은 관광만 쉬는 시간이다. 이동과 야간 휴식은 겹치지 않게 배치한다. 점심·저녁은 여행 범위에 60분을 확보할 수 있는 끼니만 넣고, 야간 출발일의 관광이나 네 끼 식사를 강제하지 않는다. 1박 2일의 다음날 귀가 날짜 조건은 유지한다.

## 승인된 서비스 고도화 범위

다음은 순차 구현할 제품 정책이다. 세부 수치·정렬·호출 상한·저장 이관은 고도화 기획서 E1~E4에만 정의한다.

1. 이동 부담·관심사 깊이·현지 여유를 기준으로 서로 다른 최대 3개 목적지를 비교한다. 근거는 실제 초안이며 인기·평점 추정은 하지 않는다.
2. 같은 시설의 세부 지점을 보수적으로 묶고 반일 단위 근접 관광과 활동 사이 여유를 구성한다. 여유는 실제 이동시간 계산값이 아니다.
3. 선택 계획의 소수 관광지만 비차단 상세 보강해 설명·허용 사진·휴무 원문·주소 복사·외부 지도 검색을 제공한다. 검색에서는 상세를 호출하지 않으며 결측은 계획을 막지 않는다.
4. 날짜·순서 이동, 관광 후보/개인 일정 추가, 숙소 메모, 시작 시각 고정으로 내 계획을 편집한다. 기존 선택·식당과 저장본을 최대 보존하며 불가 편집은 적용하지 않는다.

숙소는 사용자 입력 메모이지 추천·예약이 아니다. 음식점 추천 알고리즘 확대·출력/공유·운영 자동화·새 출발지/기간은 이번 1~4 기능 구현 범위가 아니다. 무료 공공 API·기존 키·기존 KTDB 및 관광 원천만 사용하며 새 유료 API·DB·LLM을 필수로 하지 않는다.

## MVP 비목표

- 로그인, 개인화, 서버 저장·기기 간 동기화·공개 공유 (이 기기 저장은 2단계 포함)
- 도로 경로 API, 실시간 교통, 정밀 내비게이션, 예약·결제
- 맛집 평점·랭킹, 미식 관심사·지역 프로필·추천 필터
- GPS 방문 인증, 스탬프, 컬렉션, 친구, 랭킹, 미션
- 전국 모든 지역과 모든 여행 조건의 즉시 지원
- LLM 기반 핵심 추천·일정 생성
- 상세 집 주소·읍면리 출발 검색(표준 지역 출발은 서비스 2차 고도화 범위)

## 품질 원칙

- **참고 계획의 정직성:** 매력도보다 사용 가능한 시간을 우선하되, 결과를 확정 일정이나 영업 가능 보증으로 표현하지 않는다.
- **설명 가능성:** 추천·제외·일정 배치의 근거를 표시한다.
- **불확실성 명시:** 검색 시점에 조회한 외부 데이터와 국가교통DB 기반 출발 지역↔여행 지역 자동차 일반 예상시간은 추정치·기준연도·출처를 표시하고, 실시간 교통 및 영업 가능 보장으로 표현하지 않는다. 현지 직선거리 환산은 KTDB와 별도 원천이며 [서비스 2차 고도화 정책](SERVICE_ENHANCEMENT_PHASE_2_PLAN.md)을 따른다.
- **데이터 품질 우선:** 지역 프로필은 TourAPI 공식 분류 콘텐츠·콘텐츠 ID·수집일을 근거로 한다. 선택 관심사에 해당하는 서로 다른 관광지가 3개 이상이고 실제 초안을 구성할 수 있는 권역만 추천하며, 충족한 관심사만 결과에 표시한다. 음식점 운영·휴무는 상세를 열어 확인한다.
- **점진적 확장:** 검증된 일부 지역에서 유용성을 입증한 뒤 지역을 넓힌다.

## 성공 지표

- 입력 후 목적지 후보 선택률
- 목적지 선택 후 일정 생성 완료율
- 참고 계획 생성 완료율
- 결과가 추정·결측·확인 필요 정보를 명확히 표시한 비율
- 일정 재생성·장소 교체 비율
- 추천 결과에 대한 간단한 만족 응답
- fallback 데이터 사용 비율

가장 중요한 검증은 사용자가 목적지를 정하지 않은 상태에서도 추천 결과를 납득하고 일정을 끝까지 생성하는지다.
