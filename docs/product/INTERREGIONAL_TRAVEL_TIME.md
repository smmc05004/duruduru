# 지역 간 일반 예상 이동시간 설정

## 목적

DURUDURU가 필요한 값은 청사 간 거리나 실시간 길찾기가 아니라, 사용자가 출발 지역에서 여행 지역까지 자동차로 이동할 때의 **일반적인 지역 간 예상시간**이다. 이는 내비게이션의 출발 시각별 도착 예측이나 교통 혼잡 예측이 아니라, 여행 후보를 좁히기 위한 고정 기준값이다.

MVP의 1차 원천은 한국교통연구원 국가교통DB(KTDB)의 `2025-TRNT-RO-00 (도로) 전국 지역간 네트워크(2024-2035)`다. 이 원천에는 전국 도로 링크·노드·승용차 모드·링크 기본 속성·통행시간 함수가 있다. 여객 O/D는 통행량 자료이므로 지역 간 예상시간의 직접 원천으로 사용하지 않는다.

## 준비 절차

1. KTDB 도로 네트워크의 이용 조건과 출처 표시 조건을 기록한다.
2. 부가자료의 `전국지역간 존체계(2024)`에 정의된 252개 존과, 도로 네트워크의 같은 존 중심 노드를 대표점으로 사용한다. 별도 청사 주소·좌표·지오코딩은 사용하지 않는다.
3. 2024년 네트워크의 승용차 링크 기본 비용으로 존 중심 노드 간 최단 경로를 배치 계산한다. 통행량·사고·날씨·출발 시각·실시간 교통은 입력하거나 추정하지 않는다.
4. 배치 계산 결과를 `출발 지역 ID`, `도착 지역 ID`, `편도 일반 예상시간`, `KTDB 자료 연도`, `네트워크 버전`, `대표점 기준(KTDB 252존 중심 노드)`, `적재일`로 적재한다.
5. 적재 결과에서 경로가 없거나 시간이 0 이하인 쌍은 결측으로 남긴다. PoC 고정값·직선거리 환산·임의 평균으로 채우지 않는다.

## 앱에서의 사용

`갈 수 있는 곳 찾기`를 누르면 서버는 출발 지역 ID와 후보 여행 지역 ID로 적재된 편도 일반 예상시간을 조회한다. 왕복 시간은 같은 편도 값의 두 배다.

이 데이터는 검색 시 외부 API로 호출하지 않는다. 최신 관광지·음식점 데이터와 달리, 지역 간 일반 예상시간은 KTDB 기준연도·버전이 있는 기준 데이터로 관리한다.

결과에는 “자동차 일반 예상 이동시간”, KTDB 기준연도와 데이터 갱신일을 표시한다. 실시간 교통·사고·출발 시각·개별 주소 간 내비게이션 시간으로 표현하지 않는다. 시간대별 혼잡 보정이나 교통배정은 MVP 범위 밖이다.

## 현재 사전 산출물

- 생성 도구: `scripts/build-ktdb-travel-times.mjs`
- 입력: KTDB 원본 `2024_JUNKUK_도로.in`, `전국지역간 존체계(2024).xlsx` (원본은 저장소에 복제하지 않는다.)
- 결과: `data/ktdb/interregional-travel-times-2024.json`
- 범위: 252개 존, 63,504개 출발·도착 쌍

도로로 연결되지 않는 울릉군·제주특별자치도 제주시·서귀포시는 결측으로 보존한다. 항공·선박 이동은 MVP 범위 밖이므로 이 쌍을 임의 시간으로 채우지 않는다.

## 결측과 갱신

- 출발 지역·여행 지역의 매핑 또는 시간 값이 없으면 해당 여행 지역을 추천하지 않는다.
- KTDB 새 자료를 확보하면 별도 적재 작업으로 전체 값을 갱신한다. 기존 데이터와 새 데이터의 기준연도·버전은 함께 보존한다.
- 앱 실행 중 자료를 덮어쓰지 않으며, 사용자별 경로 API 호출을 하지 않는다.
- KTDB 자료의 무료 이용·서비스 재사용 허락을 받을 수 없으면 이 원천을 사용하지 않고, 후속 OSRM 대안을 검토한다.

## 후속 대안: 자체 OSRM

KTDB 자료의 지역 단위가 DURUDURU 지원 단위와 맞지 않거나, 자동차 수단별 시간 값을 사용할 수 없는 경우에만 자체 OSRM 방식을 검토한다.

이 경우 KTDB 존 체계에 대응하는 대표점 목록과 한국 OSM 도로망으로 자체 OSRM 그래프를 만들고, 대표점 간 일반 예상시간을 배치 계산해 저장한다. 공개 OSRM 데모 서버는 소량 검증용으로만 사용하며 서비스 운영이나 대량 수집에 사용하지 않는다.
