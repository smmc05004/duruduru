# DURUDURU 제품 결정 기록

| 상태 | 항목 | 내용 | 이유 / 후속 행동 |
| --- | --- | --- | --- |
| 확정 | 핵심 경험 | 가용시간으로 목적지부터 추천한 뒤 일정 생성 | DURUDURU의 가장 중요한 차별점 |
| 확정 | 핵심 엔진 | 공공데이터 + 규칙/점수 기반 | 결과의 제약 준수와 설명 가능성 확보 |
| 확정 | 초기 데이터 전략 | 공공 API를 주기 수집·정규화하여 내부 데이터 계층에서 제공 | 외부 장애를 줄이고 마지막 정상 데이터 사용 |
| 확정 | MVP 제외 | 스탬프, 친구, 랭킹, 방문 인증 | 핵심 여행 추천 경험 검증 뒤 장기 확장 |
| 제안 | 초기 지역 | 경주, 공주/부여, 강릉 등 데이터 검증 지역부터 시작 | 전국 즉시 지원보다 데이터 품질과 일정 정확도를 우선 |
| 제안 | 초기 이동수단 | 자차를 정식 지원 대상으로 시작 | 이동시간 추정과 일정 제약을 먼저 안정화 |
| 제안 | 출발지 단위 | 주요 도시 단위 입력부터 시작 | 주소·좌표 입력과 지오코딩 복잡도를 뒤로 미룸 |
| 보류 | 최소 현지 체류시간 | 목적지별/여행 유형별 최소 기준 결정 필요 | 추천 가능 여부의 핵심 정책 |
| 보류 | 데이터 결측 처리 | 운영시간·휴무·체류시간 누락 장소의 제외 또는 보수적 fallback 기준 결정 필요 | 일정 신뢰도에 직접 영향 |
| 보류 | 일정 수정 범위 | 자동 생성만 제공할지, 장소 교체·재생성까지 포함할지 결정 필요 | MVP 화면과 엔진 범위에 영향 |
