# 제품 결정 기록

> 이 문서는 현재 MVP에 유효한 제품 결정을 한곳에 기록한다. 과거 PoC 구현 방식이나 폐기된 정적 데이터 정책은 다시 가져오지 않는다.

## 확정

| 주제               | 결정                                                                                                                                                                                                                                                                       |
| ------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 제품 경험          | 서울 출발·가용시간을 입력하면 가능한 여행 지역부터 추천하고, 선택 지역의 참고용 1박 2일 계획을 본다.                                                                                                                                                                       |
| MVP 기준 시나리오  | 서울특별시(현재 KTDB 서울 중구 존 대표 지역권) 출발의 자차, 1일차 08:00 출발, 2일차 20:00 복귀다. 입력은 출발/복귀 일시·자차·관심사이며 출발지 선택·검색은 제공하지 않는다.                                                                                                |
| 지역권 범위        | 경주·공주·강릉은 초기 예시·검증 지역이다. 목적지 모수는 KTDB 2024 전국 252개 지역권이고, 실제 추천 가능 범위는 KTDB↔TourAPI 법정동 매핑 가능·선택 카테고리 근거 수 충족 지역의 부분집합이다.                                                                               |
| 지역 간 이동시간   | KTDB 2024 252존 중심 노드 간 승용차 기본 링크 비용으로 사전 산출한 일반 예상시간만 쓴다. 검색 중 경로 API를 호출하지 않는다.                                                                                                                                               |
| 지역 내부 이동     | 관광지↔관광지, 관광지↔음식점, 음식점↔다음 장소의 이동시간은 계산·표시·일정 제약에 사용하지 않는다.                                                                                                                                                                         |
| 관심사·지역 프로필 | TourAPI 공식 분류만 쓴다: 자연 `A01`, 역사 `A0201`, 휴양 `A0202`, 문화 `A0206` 또는 콘텐츠유형 `14`, 레저 `A03` 또는 콘텐츠유형 `28`. 휴양·레저는 UI에서 하나로 묶을 수 있으나 원천 코드와 각 근거는 분리 보존한다. 임의 지역 평판·태그는 쓰지 않는다.                     |
| 지역 프로필 인덱스 | TourAPI 공식 분류 콘텐츠의 수·콘텐츠 ID·수집일을 근거로 하루 1회 JSON 인덱스를 만든다. 분류 코드가 비었거나 카테고리별 최소 근거 수를 충족하지 못하면 해당 카테고리 추천에서 지역을 제외한다. 이는 fallback이 아닌 명시적 MVP 지원 범위다.                                 |
| 후보 검색 흐름     | 검색은 서울→전국 252존 시간 적합성 필터 후, 매핑 가능·카테고리 근거 충족 지역의 정기 수집 프로필 인덱스를 평가한다. 그 후보에만 음식점 목록 기본 정보를 제한 동시성·페이지네이션으로 연결하고 최종 3곳을 고른다.                                                           |
| 음식점             | 미식은 관심사·지역 프로필·추천 필터에서 제거한다. 식사 블록에는 TourAPI 음식점 목록 기본 정보에서 안정적인 콘텐츠 ID 순으로 한 곳을 배치한다. 메뉴·운영시간·휴무는 음식점 클릭 시 서버 Route Handler가 `detailIntro2`로 조회하며, 상세 결과는 일정 시간표를 바꾸지 않는다. |
| 시간표 규칙        | 관광지와 음식점은 각각 1시간이다. 21:00~~07:00은 휴식으로 고정한다. 점심은 11:30~~13:30, 저녁은 17:30~19:30에 각각 1시간을 반드시 배치한다.                                                                                                                                |
| 제외 범위          | LLM 핵심 추천, 평점·리뷰·랭킹, 미식 필터, 지역N문화·모범음식점·대표음식 시드, 음식점 운영시간 검색 필터, 유료 API, 실시간 교통, 도로 길찾기, 정밀 내비게이션, 예약·결제는 MVP 범위 밖이다.                                                                                 |

## 현재 준비 상태와 교체 대상

- KTDB 252존 기반 지역 간 일반 예상시간 테이블은 `data/ktdb/interregional-travel-times-2024.json`에 생성돼 있다.
- TourAPI 법정동 코드와 KTDB 252존의 전국 목적지 매핑, TourAPI 공식 분류 기반 지역 프로필 인덱스는 추천 전제다.
- 현재 코드의 고정 3개 목적지·역사/자연/문화/미식 임의 태그·정적 어댑터는 이 문서 기준선과 불일치하므로 교체한다.
- 서울 외 출발지 확장을 막지 않도록 데이터 계약은 출발/도착 지역 ID를 분리한다. 출발지 선택·검색은 P1 이후다.

## 보류

- 시간대별 혼잡, 실시간 교통, 상세 주소·장소 간 이동시간, 모든 252개 지역의 완전 커버
- 복수 대체 음식점, 동선 최적화, 미식 관심사, 일정 재생성·장소 교체, 대중교통·날씨·예산
