# 긴 여유시간 보완 기획

> 기준일: 2026-09-14. 사용자에게 승인받은 소규모 고도화 범위를 구체화한 PM 기획이며 총괄 검토를 완료한 구현 기준이다. 목적지 추천 재작업 PR #77 이후의 선택 계획을 대상으로 한다. 작업 브랜치에서 구현·직접 점검을 완료했으며 실제 검증과 미병합 상태는 [작업 계획](../development/LONG_GAP_ENRICHMENT_WORK_PLAN.md)에 기록한다.

## 문제와 범위

일정 중 150분처럼 두 시간이 넘는 낮 여유가 반복되면 사용자는 여행 시간을 충분히 활용하지 못한다고 느낀다. 약 한 시간은 쉬거나 자유롭게 둘러볼 수 있도록 남기면서, 기존 관광을 재배치하거나 관심사에 맞는 가까운 관광을 추가한다. 이 기능은 P1 선택 계획 품질 개선이다.

새 필수 입력 없이 신규 선택 계획에 적용하고, 이미 편집했거나 저장한 계획은 사용자가 `긴 여유시간 보완`을 실행할 때만 적용한다. 목적지 순위·세 역할·추천 자격을 바꾸지 않는다. 새로운 지역·기간·관심사·API·원천 수집·실시간 경로·운영시간 자동 판정은 추가하지 않는다.

이 문서는 긴 여유 보완의 단일 기준이다. 검색 추천은 [R3 확정 정책](RECOMMENDATION_QUALITY_RECOVERY.md), 기존 편집·상세는 [E3/E4](SERVICE_ENHANCEMENT_SPEC.md), 이동 추정은 [서비스 2차 고도화](SERVICE_ENHANCEMENT_PHASE_2_PLAN.md)를 유지하며 아래 명시한 경계만 우선한다.

## L1. 적용 시점과 추천 경계

1. 검색의 후보 초안 생성·관광 하루 3곳/전체 6곳·R3 역할 정렬은 유지한다. `overnight`와 `interestRich`의 현지 자유시간 240분 조건은 **목적지를 선택하기 전 검색 초안의 후보 적합성 조건**이다. 선택 후 여유를 관광으로 사용하는 보완 계획에 240분을 다시 강제하거나, 줄어든 여유 때문에 목적지와 역할을 소급 변경하지 않는다.
2. 신규 목적지를 선택하면 기존 초안을 먼저 표시하고 기존 음식점 최초 조회·배정·이동 재계산이 성공·부분 성공·실패 중 하나로 끝난 뒤 현재 계획에 자동 보완을 한 번 시도한다. 실패 시에도 식사 시간과 미확정 이동을 보존한 상태를 기준으로 한다. 음식점 재시도·관광 상세 응답마다 보완을 다시 시작하지 않는다.
3. 자동 적용은 선택 당시 계획 ID와 편집 세대가 그대로일 때만 가능하다. 사용자가 그 사이 편집하거나 저장·복원·다른 목적지 선택을 했다면 늦은 결과를 적용하지 않는다. 사용자가 삭제한 장소를 자동으로 되살리지 않는다. 이때 필요하면 현재 계획에서 명시적 보완을 실행한다.
4. 기존 계획의 일반 교체·삭제·체류시간·순서 편집은 해당 편집만 실행한다. `긴 여유시간 보완`이 현재 계획의 비고정 관광 시각·순서를 조정하고 새 관광을 추가할 수 있음을 실행 전에 짧게 알린다. 저장본 복원은 자동 보완·자동 외부 조회·자동 저장을 하지 않는다.
5. 검색 후보의 초안과 추천 근거를 그대로 보존하고 보완 결과의 블록·관광 수·자유시간은 선택 계획 지표로 별도 계산한다. 화면은 `선택 후 긴 여유시간을 보완했어요`와 추가 장소 수/재배치 여부를 표시한다. 검색 초안의 자유시간을 최종 계획의 현재 자유시간처럼 표시하지 않는다.

## L2. 대상과 반드시 남기는 여유

- 대상은 현지 체류 중 07:00~21:00의 실제 연속 `free`가 **120분 초과**인 구간이다. 정확히 120분 이하는 그대로 두며, 야간 휴식·운전·식사·관광·개인 일정·현지 이동 예약은 대상 시간이 아니다.
- 처리 시작 시 대상이 된 원래 구간의 시작·끝을 보존한다. 그 구간을 보완한 뒤에도 **원래 시간 구간 안에 연속된 순수 자유시간 60분 이상**이 남아야 한다. 두 개의 30분을 합쳐 충족했다고 보지 않는다. 실제 이동 추정과 미확정 이동 예약을 자유시간에 포함하지 않는다.
- 보완하는 날은 최종 순수 자유시간 총합도 최소 60분을 확보한다. 이는 위 구간의 60분을 포함한 합이며 중복 차감하지 않는다. 보완 대상이 없는 날에는 기존 활동일 최소 30분을 유지하고, 관광할 시간이 없는 날에 관광이나 60분 여유를 새로 강제하지 않는다.
- 자유시간 블록을 표시상 쪼개거나 이름만 바꿔 120분 이하로 만든 것은 개선이 아니다. 실제 관광의 배치 변경 또는 새 시설 방문이 있어야 한다. 마지막에 인접한 순수 자유시간은 하나로 합쳐 판정한다.
- 하루 관광은 이번 보완 규칙을 쓰는 선택 계획에서 최대 4곳, 전체 최대 8곳까지 허용한다. 4곳을 채우는 것이 목표는 아니며 한도 때문에 관광·개인 일정·식사·휴식을 삭제하지 않는다. 개인 일정 한도는 기존 전체 4개를 유지한다.

## L3. 유한한 보완 순서

### 기존 관광 재배치 우선

처음에는 장소를 추가하지 않고 해당 날짜의 기존 관광을 조정한다. 끼니, 지역 간 이동, 야간 휴식, 개인 일정, 시작 시각 고정 관광을 경계로 나눈 **같은 구간 안**에서 비고정 관광의 시작 시각과 상대 순서를 검토한다. 날짜 이동·끼니 전후 이동·개인 일정 전후 이동·고정 관광을 넘어서는 이동은 이번 자동/명시 보완 범위가 아니다. 다른 날의 긴 여유를 해소하기 위해 관광을 날짜 간 옮기지 않는다.

기존 관광 ID·방문시간·장소 유지 설정은 보존한다. `장소 유지`는 기존처럼 선택 보존이므로 시각 고정이 없는 해당 관광은 구간 안 재배치할 수 있다. 시작 시각 고정은 방문 구간 전체를 그대로 유지한다. 개인 일정은 시각 고정 여부와 관계없이 이번 보완에서는 ID·시각·내용을 모두 보존한다.

끼니의 ID·시각·60분·현지/이동 구분·선택 식당, 출발·귀가 운전 시각, 야간 휴식과 숙소 메모도 유지한다. 이 경계를 바꿔야만 가능한 개선은 시도하지 않는다.

### 남은 긴 여유에 가까운 관광 추가

재배치 후에도 대상이 남으면 현재 계획에 보유한 선택 권역 관광 후보에서 60분 방문을 하나씩 검토한다. 새 목록이나 관광 상세를 조회해 후보를 늘리지 않는다.

1. 요청 관심사 중 하나 이상에 공식 분류로 해당해야 한다. 여행 전체 미사용 콘텐츠 ID이며 강한 중복·확인된 동일 시설·시설 의심 묶음 모두 기존 방문과 겹치지 않는 후보를 쓴다. 보완에서는 다른 시설 후보가 없다고 동일 시설 예외로 채우지 않는다. 기존의 사용자 직접 추가 예외는 유지한다.
2. 추가 위치 바로 앞 또는 뒤의 같은 날 실제 관광·식당 중 유효 좌표가 있는 장소와 직선거리 5km 이내여야 한다. 새 관광 좌표가 없거나 비교 가능한 이웃이 없으면 자동 추가 대상에서 제외한다. 5km는 기존 근접 선정의 제품 범위이며 도보·도로 접근성 보증이 아니다.
3. 삽입으로 바뀌는 앞→새 관광→뒤 연결을 `straight-line-v1`으로 다시 계산하고, 없어지는 기존 앞→뒤 연결은 제거한다. 다른 이웃의 좌표가 없으면 기존 정책대로 미확정 15분을 확보한다. 지역 대표점·숙소·밤사이 가상 연결은 만들지 않는다. 이동 분과 관광 60분을 반영한 뒤 L2의 여유 및 모든 고정 경계를 충족해야 한다.
4. 가능한 후보는 추가되는 현지 이동 예약 분이 적은 순 → 요청 관심사에 해당하는 당일 미사용 세부 유형이 있는 순 → 콘텐츠 ID 순으로 검토한다. 결측 이동을 짧은 확정 이동으로 취급하지 않도록 변경 연결이 모두 추정 가능한 후보를 우선한다. 원천 배열 순서·조회 시각·무작위를 정렬 근거로 쓰지 않는다.
5. 상한과 조건을 만족하는 개선만 채택하고 다음 남은 긴 구간을 검토한다. 한 실행에서 같은 콘텐츠 ID·같은 배치안을 반복 탐색하지 않고, 순서와 후보 개수의 유한한 범위에서 끝낸다. 추가 상한은 남은 하루 4곳/전체 8곳의 슬롯이다. 모든 관광을 채우는 전역 최적화나 120분 초과 구간의 완전 제거를 보장하지 않는다.

### 선택·개선 판정과 실패 보존

날짜 오름차순, 그날 긴 구간은 길이 내림차순·시작 시각 오름차순으로 다룬다. 기존 관광 재배치의 후보 중 L2와 보존 조건을 모두 통과한 결과를 비교한다. 우선 그날의 `각 연속 free에서 120분을 넘는 분의 합`을 줄이고, 동률이면 가장 긴 free를 줄인다. 두 지표가 모두 그대로면 변화로 채택하지 않는다. 목표를 이미 충족한 구간을 다른 곳에 옮겨 새 긴 구간을 만들고 성공이라고 표시하지 않는다.

동일 개선 결과에서는 바뀐 기존 관광 시작 시각의 개수가 적은 순 → 시작 시각 변동 절대 분 합이 적은 순 → 최종 시작 시각/콘텐츠 ID 순으로 결정한다. 추가 역시 동일한 개선 판정을 통과해야 하며 보완 전에 이미 충족했던 요청 관심사는 유지한다. 앞 단계에서 보존한 원래 구간의 연속 60분을 다음 추가가 소비하지 않는다.

시도는 복사한 계획에서 수행하고 전체 시간·연결·고정·수량 검증 후 성공 결과만 원자 적용한다. 불가능한 후보는 다음 후보를 검토한다. 개선이 하나도 없거나 검증에 실패하면 기존 계획·저장 상태·식당·고정·메모를 그대로 반환한다. 실행 도중 다른 편집이 들어오면 결과를 버린다.

## L4. 정보 조회·저장·표시

- 관광 자동 상세는 최종 신규 계획에 실제 배치된 관광을 시간순으로 최대 6개, 원천 요청 최대 12회라는 기존 E3 예산 안에서만 보강한다. 이미 시작/완료한 자동 요청도 같은 예산에 포함하고 보완 때문에 예산을 초기화하지 않는다. 최초 6개를 대상으로 자동 작업이 이미 시작되었으면 보완으로 최종 시각순이 바뀌어도 대상 목록과 예산을 재설정하지 않는다. 이때 추가 관광은 명시적 장소 클릭으로 조회한다. 7~8번째 또는 자동 대상에서 제외된 추가 관광도 사용자가 해당 장소를 클릭할 때 기존 개별 상세 예산으로 조회한다. 기존 계획의 명시 보완은 자동 상세 0회다.
- 음식점 최초 조회 상한은 기존 최대 3지역·9회·동시성 2를 유지한다. 보완 때문에 관광 하위 지역이 달라져도 목록 재요청을 자동으로 추가하지 않는다. 선택 식당은 보존하고 위치 확인 안내와 기존 `식당 후보 다시 확인`을 사용한다. 재시도 응답으로 이미 보완·편집된 관광을 초기화하지 않는다.
- 보완에 성공한 새 선택 계획에는 기존 검색 알고리즘 버전과 구분되는 보완 규칙 버전 및 적용 여부를 보존한다. 무변경 신규 계획은 기존 3/6 한도와 규칙 버전을 유지하며, 시도했다는 이유만으로 버전을 올리지 않는다. 저장 정규화와 시간 검증은 새 4/8 계획을 유효하게 받아야 하며, 불러온 뒤 일반 편집에도 새 한도를 유지한다. 정확한 필드·버전명은 employee가 계약으로 기록한다.
- 구 저장본은 당시 규칙·3/6 한도·시각을 그대로 복원한다. 명시 보완이 성공할 때만 현재 메모리 계획을 새 규칙으로 전환하며 사용자의 저장 동작 전에는 저장 원본을 바꾸지 않는다. 무변경·실패는 버전만 올리지 않는다. 4/8 계획과 구 역할·구 이동 버전의 읽기 호환을 함께 유지한다.
- 성공은 `긴 여유시간을 보완했어요`와 `관광 1곳 추가`/`기존 관광 시간 조정`처럼 실제 변경만 알린다. 여전히 긴 구간이 남으면 숨기지 않는다. 후보 없음·관광 한도·이동/여유 부족·고정 경계 충돌을 구분해 `조건에 맞는 가까운 관광지가 없어 기존 여유시간을 유지했어요`처럼 설명한다. 모든 여유를 줄이겠다고 약속하지 않는다.
