# 대표음식·음식점 데이터 정책

## 목적

식사는 관심사와 무관하게 일정에 반드시 포함한다. DURUDURU는 맛집 순위를 만들지 않고, 지역 대표음식을 취급하며 해당 식사 시간에 이용 가능한 음식점을 추천한다.

음식 데이터는 목적지 후보가 관광지·왕복 시간 조건을 통과한 뒤에만 조회한다. 최종 추천 후보에는 관광지와 점심·저녁 음식점 정보가 모두 연결돼 있어야 한다.

## 데이터 원천과 역할

| 원천                                                               | 역할                                        | 사용하는 데이터                                                               |
| ------------------------------------------------------------------ | ------------------------------------------- | ----------------------------------------------------------------------------- |
| 한국문화원연합회 지역N문화 「향토음식과 지역이야기」 공식 다운로드 | 지역 대표음식의 시드                        | 시·군·구, 음식명, 원문 표기, 별칭 근거, 제공기관·확인일                       |
| 한국관광공사 TourAPI KorService2                                   | 최신 음식점 후보와 실제 메뉴·운영 정보      | 음식점 ID, 이름, 주소·좌표, `firstmenu`·`treatmenu`, 운영시간·휴무, 조회 시각 |
| 지방행정 인허가 데이터개방 모범음식점 표준데이터                   | 공식 지정 여부와 주된 음식 종류의 교차 확인 | 업소명·주소, 영업 상태, 주된음식종류, 지정일·갱신일                           |

지역N문화는 대표음식 후보의 근거이고, TourAPI는 음식점의 최신 운영·메뉴 근거다. 모범음식점 데이터는 위생·시설 지정 데이터이므로 단순 빈도로 대표음식을 정하지 않으며, 공식 지정 여부라는 보조 신호로만 쓴다.

## 후보 검색 중 처리

1. 청사 간 일반 예상 이동시간과 관심사 관광지로 1차 목적지 후보를 만든다.
2. 1차 후보 지역에만 TourAPI 음식점·상세 정보를 서버에서 조회한다.
3. 지역N문화의 대표음식 시드와 음식점 메뉴를 별칭까지 포함해 연결한다.
4. 모범음식점 데이터로 영업 상태·공식 지정 여부·주된 음식 종류를 교차 확인한다.
5. 식사 시간에 1시간 이용 가능한 점심·저녁 후보가 모두 있는 지역만 최종 추천 후보로 남긴다.

TourAPI 서비스 키는 `TOUR_API_SERVICE_KEY`로 서버에서만 사용한다. 음식점·대표음식 원천의 응답과 조회 시각은 검색 스냅샷에 보존하고, 브라우저에는 정규화한 결과만 전달한다.

## 대표음식·음식점 연결 규칙

- 대표음식 근거는 공식 지정 대표음식, 공식 향토음식, 음식점 메뉴에서 도출한 후보 순으로 신뢰도를 구분해 보존한다.
- 메뉴 텍스트는 대표음식명과 별칭을 함께 비교한다. 단순 부분 문자열만으로 연결하지 않고, 지역·대표메뉴·주소·분류 등 원문 맥락을 함께 확인한다.
- 운영시간·휴무 정보는 점심(11:30~~13:30)과 저녁(17:30~~19:30)에 각각 1시간을 배치할 수 있는지 판정한다. 운영시간 형식을 해석하지 못하거나 휴무 여부가 확인되지 않으면 후보에서 제외한다.
- 평점·리뷰·인기순·광고 순위는 사용하지 않는다.

## 최종 음식점 선정

대표음식 취급과 식사 시간 운영 조건을 통과한 후보가 여럿이면 다음 순서로 한 곳을 고른다.

1. 공식 지정 여부
2. 해당 식사와 연결된 관광지까지의 직선거리
3. 안정적인 장소 ID 오름차순

공식 지정 후보가 없으면 전체 후보에서 2단계부터 적용한다. 직선거리는 음식점 하나를 일관되게 고르기 위한 동점 해소 기준이며, 이동시간·일정 제약·사용자 화면에는 사용하지 않는다.

## 결측과 범위

- 대표음식 근거, 메뉴 연결, 운영·휴무 정보 중 필요한 정보가 없으면 해당 음식점을 추천하지 않는다.
- 점심 또는 저녁 후보를 만들 수 없으면 해당 지역은 최종 추천 후보에서 제외한다.
- 정적 음식점 fallback, 상용 지도·리뷰 플랫폼 스크래핑, 임의의 대표음식 상수는 사용하지 않는다.
- 지원 지역을 추가할 때는 세 원천의 지역별 데이터 가능 여부와 별칭을 먼저 확인한다.
