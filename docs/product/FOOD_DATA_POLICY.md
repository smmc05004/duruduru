# MVP 음식점 데이터 정책

## 범위

식사는 관심사와 무관하게 점심·저녁 블록에 반드시 배치한다. 미식은 관심사·지역 프로필·목적지 추천 필터에 포함하지 않는다. 다만 사용자가 목적지를 선택한 뒤 식사 음식점을 고를 때 지역N문화의 공식 대표음식과 모범음식점의 공식 지정·음식 종류 근거를 우선순위화에 사용한다.

이 근거는 여행 지역을 후보에서 제외하는 조건이 아니며, 선택 후 음식점 후보를 고르는 근거다. 전국 음식점 정규화 데이터셋은 만들지 않는다. 평점·리뷰·랭킹은 사용하지 않는다.

## 검색 스냅샷

서울 출발→전국 252존 시간 필터를 통과하고, TourAPI 지역 매핑과 관심사 카테고리 근거를 충족한 지역에만 음식점 목록을 제한 동시성·페이지네이션으로 조회한다.

검색 스냅샷에는 TourAPI 음식점 콘텐츠 ID, 이름, 주소·좌표, 분류, 대표 이미지, 수집일 등 목록 기본 정보와 지역N문화 대표음식·모범음식점 근거를 보존한다. 지역N문화·모범음식점은 일일 지역 데이터 인덱스에 미리 결합하거나 준비된 정적 공식 원천으로 조회한다. 일정은 대표음식 근거, 모범음식점 공식 지정·음식 종류 근거, 안정적인 콘텐츠 ID 순으로 음식점 하나를 식사 블록에 배치한다. 대표음식 근거가 없으면 모범음식점·목록 기본 정보의 안정적 기준으로 고른다. 메뉴·운영시간·휴무의 결측은 후보 제외 사유가 아니다.

## 상세 확인

사용자가 음식점을 클릭할 때만 서버 Route Handler가 해당 콘텐츠 ID로 TourAPI `detailIntro2`를 호출한다. 이 요청에서 메뉴·운영시간·휴무 등 상세 정보를 보여 주고, 실제 방문 전 확인이 필요하다고 안내한다.

상세 호출의 성공·실패는 이미 만든 일정의 후보 순서·식사 블록·시간표를 바꾸지 않는다. 실패는 해당 음식점 상세의 재시도 상태로만 보인다.

## 제외 범위

- 음식점 메뉴 또는 운영시간을 검색 단계에서 조회·해석·필터링하는 처리
- 음식점 품질 순위, 평점·리뷰·광고 순위
- 상용 지도·리뷰 플랫폼 스크래핑 및 정적 음식점 fallback

## 준비 의존성

지역N문화 다운로드·이용 조건과 모범음식점 공식 원천의 갱신·정규화는 식사 음식점 우선순위화의 현재 준비 의존성이다. 그러나 TourAPI 공식 카테고리 지역 프로필 생성이나 여행 지역 후보 필터를 막는 의존성은 아니다.
