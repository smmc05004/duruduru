# MVP 음식점 데이터 정책

## 범위

식사는 관심사와 무관하게 점심·저녁 블록에 반드시 배치한다. MVP에서 음식점은 **TourAPI 음식점 목록의 기본 정보**만 사용한다. 미식은 관심사·지역 프로필·목적지 추천 필터에 포함하지 않는다.

지역N문화 대표음식, 모범음식점, 메뉴 기반 대표음식 연결은 MVP 후보 선정의 의존성이 아니다. 전국 음식점 정규화 데이터셋도 만들지 않는다. 평점·리뷰·랭킹은 사용하지 않는다.

## 검색 스냅샷

서울 출발→전국 252존 시간 필터를 통과하고, TourAPI 지역 매핑과 관심사 카테고리 근거를 충족한 지역에만 음식점 목록을 제한 동시성·페이지네이션으로 조회한다.

검색 스냅샷에는 TourAPI 음식점 콘텐츠 ID, 이름, 주소·좌표, 분류, 대표 이미지, 수집일 등 목록 기본 정보만 보존한다. 일정은 이 정보에서 안정적인 콘텐츠 ID 순으로 음식점 하나를 식사 블록에 배치한다. 메뉴·운영시간·휴무의 결측은 후보 제외 사유가 아니다.

## 상세 확인

사용자가 음식점을 클릭할 때만 서버 Route Handler가 해당 콘텐츠 ID로 TourAPI `detailIntro2`를 호출한다. 이 요청에서 메뉴·운영시간·휴무 등 상세 정보를 보여 주고, 실제 방문 전 확인이 필요하다고 안내한다.

상세 호출의 성공·실패는 이미 만든 일정의 후보 순서·식사 블록·시간표를 바꾸지 않는다. 실패는 해당 음식점 상세의 재시도 상태로만 보인다.

## 제외 범위

- 지역 대표음식 시드·지역N문화 다운로드·모범음식점 데이터의 수집·정규화
- 음식점 메뉴 또는 운영시간을 검색 단계에서 조회·해석·필터링하는 처리
- 음식점 품질 순위, 평점·리뷰·광고 순위
- 상용 지도·리뷰 플랫폼 스크래핑 및 정적 음식점 fallback
