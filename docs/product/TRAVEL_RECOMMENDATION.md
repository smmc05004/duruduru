# 여행 장소 추천 방법

## 목적

DURUDURU는 목적지를 모르는 사용자가 주어진 시간으로 목적지를 비교하고 수정 가능한 1박 2일 참고 계획을 만들도록 돕는다. 검증된 표준 출발 지역, 자차, 기존 관심사 입력을 사용한다. 분 단위 실행·영업·실시간 교통을 보증하는 서비스가 아니다.

## 구현 기준

기준선은 [MVP 2단계 기획서](MVP_PHASE_2.md)와 [서비스 고도화 기획서](SERVICE_ENHANCEMENT_SPEC.md) E1~E4다. 다음 구현의 공식 분류·사전 데이터·목적 적합성·역할 선택은 [관광 데이터·목적 적합성 기획서](TOURISM_RECOMMENDATION_UPGRADE.md)가 교체 기준이다. 현재는 계획 완료/구현 미착수이며 모델 변경 후 사용자 지시를 기다린다. 시간·식사·현지 이동·편집의 기존 정책은 유지한다.

1. 지원 입력·1박 2일·KST 날짜를 서버에서 검증한다. 출발·귀가 이동 시각은 제한하지 않는다. 여행 범위 안 식사·낮 관광을 확보할 수 없으면 시간 조건 불가로 안내한다.
2. KTDB 252존과 TourAPI 법정동 매핑 지역을 특별시·광역시·특별자치시 또는 도 지역 시·군 단위로 합친다. 일반구는 상위 시에 포함하고 출발지와 같은 권역은 모든 하위 구를 포함해 제외한다.
3. 기존 지역 프로필에서 공식 관심사 관광지 3개 이상인 그룹으로 실제 시간 초안을 만든다. 식당 목록·상세는 검색 단계에서 호출하지 않는다.
4. 실제 초안 지표로 관심사 깊이·이동 부담·여유의 역할별 최대 3개 목적지를 중복 없이 선택한다. 다음 구현은 새 기획서 D4의 interest 우선 선택·실제 방문 중심 근거 점수를 적용한다. 프로필 원천 총개수로 순위를 정하거나 부족한 후보를 임의 생성하지 않는다.
5. 목적지 선택 뒤 실제 관광 장소 주변 하위 지역의 음식점 목록만 제한 조회한다. 현지 식사에는 중복 없는 식당을 연결하고 이동 중 식사는 자유 식사로 둔다.
6. 선택 계획의 실제 관광지만 E3 상한 안에서 비차단 상세 보강한다. 사용자는 기존 편집에 더해 E4 날짜·순서 이동/추가/시각 고정을 이용한다. 식당 교체·기기 저장을 유지하고 불가 편집은 이전 계획을 보존한다.

## 공식 분류·장소 근거

공식 lclsSystm1/2/3를 우선해 5개 관심사와 연결한다. 역사 HS는 실측됐으며 전체 대응표는 공식 코드 목록으로 확정한다. 기존 자연 A01, 역사 A0201, 휴양 A0202, 문화 A0206 또는 유형14, 레저 A03 또는 유형28은 새 분류가 없을 때의 하위 호환이다. 새 분류를 확인하지 않고 cat 결측을 무분류로 취급하지 않는다. 의미 변경·미해석 분류는 새 기획서 D1을 따른다. 미식은 관심사 필터가 아니다. 콘텐츠 ID는 여행 전체 중복 배치하지 않으며 이름·주소·좌표가 함께 뒷받침할 때만 중복 후보를 보수적으로 억제한다. 가까운 좌표만으로 관광지 전체를 병합하지 않는다.

중심 관광지 근거는 별도 사전 수집 후 기존 관광지에 확실히 연결된 경우만 실제 일정의 가점으로 사용한다. 지역 내 연계 방문 중심성이며 전국 인기·역사적 가치 순위가 아니다. 미연결을 임의 장소로 대체하지 않는다. 연결·시설 중복·표시는 새 기획서 D3~D4를 따른다.

E2 시설 의심 묶음은 원본을 삭제하지 않고 자동 초안에서 중복 사용을 억제하는 제품 근거다. 반일별 가까운 장소를 우선하되 관광공사의 공식 시설 묶음이나 실제 도로 동선이라고 표현하지 않는다. 사용자의 명시적 추가는 안내 후 예외를 허용한다.

## 시간·선정 경계

KTDB는 출발↔여행지 일반 운전시간이다. 운전·식사·관광은 겹치지 않는다. 21:00~07:00에는 관광을 쉬지만 지역 간 이동은 가능하다. 휴식은 야간 현지 체류 구간에만 배치한다. 여행 범위 안에 60분을 확보할 수 있는 점심·저녁을 현지 또는 이동 중에 배치하고 이동 중 식사 분은 운전 분과 별도로 더한다. 관광 기본 60분 및 관광하는 날의 현지 자유시간 30분을 배치하고 결과·후보·편집에 동일 엔진을 쓴다.

여행지 내부 이동은 [서비스 2차 고도화 정책](SERVICE_ENHANCEMENT_PHASE_2_PLAN.md)의 `straight-line-v1`으로 같은 날 연속 관광·식사·개인 장소 사이 시간을 확보한다. 유효 좌표는 직선거리 기반 추정, 결측은 미확정 예약으로 구분한다. 도로 경로·실시간 소요시간이 아니며 계획 기본 영역에 추정 안내를 표시한다. 상세 운영정보로 모든 영업 여부를 자동 판정하지 않는다.

고도화의 활동 사이 여유는 E2에 따라 하루 최소 자유시간 안에 포함하며, 중복 차감하지 않는다. 관광·개인 일정의 날짜/시각 편집은 E4로 검증하고 숙소 메모를 밤 휴식과 이중 계산하지 않는다. 운영 원문의 매우 단순한 요일 규칙에 한해서만 방문일 주의를 표시하며 자동 제외·재배치하지 않는다.

## 표시·예외

후보 카드는 실제 초안 방문 장소와 관심사 충족, 왕복시간, 현지 활동·자유시간을 표시한다. 계획은 출발·도착·귀가 출발·복귀 완료를 구분하고 식사·관광·휴식·자유시간을 보여준다. 근거는 출처·기준연도·프로필 생성일·목록 조회일을 구분한다.

시간 불가·분류 부족·API 실패는 구분한다. 음식점 실패는 관광을 유지하고 식사 영역 재시도, 상세 실패는 해당 상세 안 재시도다. PoC·임의 시간·임의 식당으로 대체하지 않는다. 방문 전 운영·휴무·예약 재확인을 안내한다.

원천·호출은 [API 흐름](API_FETCH_FLOW.md), [음식 정책](FOOD_DATA_POLICY.md), [거리 계산](DISTANCE_CALCULATION.md), [지역 간 시간 설정](INTERREGIONAL_TRAVEL_TIME.md)을 따른다.
