# 여행 장소 추천 방법

## 목적

DURUDURU는 목적지를 모르는 사용자가 주어진 시간으로 목적지를 비교하고 수정 가능한 1박 2일 참고 계획을 만들도록 돕는다. 서울·부산 출발, 자차, 기존 관심사 입력을 유지한다. 분 단위 실행·영업·실시간 교통을 보증하는 서비스가 아니다.

## 구현 기준

추천·시간표·편집의 구체적 알고리즘과 수용 기준은 [MVP 2단계 기획서](MVP_PHASE_2.md) P2-01~P2-05가 단일 기준이다. 아래는 사용자 흐름과 원천 경계다.

1. 지원 입력·1박 2일·KST 날짜를 서버에서 검증한다. 출발·복귀와 네 식사·휴식 경계가 공존할 수 없는 입력은 시간 조건 불가로 안내한다.
2. KTDB 252존과 TourAPI 법정동 매핑 지역을 특별시·광역시·특별자치시 또는 도 지역 시·군 단위로 합친다. 일반구는 상위 시에 포함하고 출발지와 같은 권역은 모든 하위 구를 포함해 제외한다.
3. 기존 지역 프로필에서 공식 관심사 관광지 3개 이상인 그룹으로 실제 시간 초안을 만든다. 식당 목록·상세는 검색 단계에서 호출하지 않는다.
4. 초안에 실제 배치된 관심사·관광 개수·분류 다양성·근접성·왕복시간으로 최대 3개 목적지를 비교한다. 프로필 원천 총개수로 순위를 정하거나 부족한 후보를 임의 생성하지 않는다.
5. 목적지 선택 뒤 실제 관광 장소 주변 하위 지역의 음식점 목록만 제한 조회한다. 현지 식사에는 중복 없는 식당을 연결하고 이동 중 식사는 자유 식사로 둔다.
6. 사용자는 장소 고정·교체·시간 수정·삭제, 식당 교체, 이 기기 저장과 관광/음식점 클릭 상세를 이용한다. 불가 편집은 이전 계획을 보존한다.

## 공식 분류·장소 근거

자연 A01, 역사 A0201, 휴양 A0202, 문화 A0206 또는 콘텐츠유형 14, 레저 A03 또는 유형 28을 사용한다. 미식은 관심사 필터가 아니다. 분류가 없는 레코드를 임의 분류하지 않는다. 콘텐츠 ID는 여행 전체 중복 배치하지 않으며 이름·주소·좌표가 함께 뒷받침할 때만 중복 후보를 보수적으로 억제한다. 가까운 좌표만으로 관광지 전체를 병합하지 않는다.

## 시간·선정 경계

KTDB는 출발↔여행지 일반 운전시간이다. 운전·식사·관광은 겹치지 않으며 21:00~07:00은 휴식이다. 양일 점심·저녁 각 60분을 현지 또는 이동 중에 확보하고 이동 중 식사 분은 운전 분과 별도로 더한다. 관광 기본 60분 및 현지 자유시간을 배치하고 결과·후보·편집에 동일 엔진을 쓴다.

여행지 내부 이동시간은 계산하지 않는다. 좌표 직선거리는 관광 묶음·식당 선정의 보조 기준이며 도로 경로·소요시간으로 환산하지 않는다. 상세 운영정보로 모든 영업 여부를 자동 판정하지 않는다.

## 표시·예외

후보 카드는 실제 초안 방문 장소와 관심사 충족, 왕복시간, 현지 활동·자유시간을 표시한다. 계획은 출발·도착·귀가 출발·복귀 완료를 구분하고 식사·관광·휴식·자유시간을 보여준다. 근거는 출처·기준연도·프로필 생성일·목록 조회일을 구분한다.

시간 불가·분류 부족·API 실패는 구분한다. 음식점 실패는 관광을 유지하고 식사 영역 재시도, 상세 실패는 해당 상세 안 재시도다. PoC·임의 시간·임의 식당으로 대체하지 않는다. 방문 전 운영·휴무·예약 재확인을 안내한다.
