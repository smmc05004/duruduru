# 여행 장소 추천 방법

## 목적

DURUDURU는 목적지를 정하지 못한 사용자가 출발지와 가용시간 안에 갈 수 있는 국내 여행지를 고르고, 선택한 지역의 1박 2일 참고 계획을 확인하도록 돕는다. 초기 MVP의 기준 시나리오는 자차로 1일차 08:00에 출발해 2일차 20:00까지 복귀하는 여행이다.

추천과 일정 생성은 최신 공공 관광 데이터와 규칙 기반 계산으로 수행한다. LLM, 평점·리뷰·랭킹, 예약·내비게이션·실시간 교통은 사용하지 않는다.

## 후보 검색과 목적지 선택

`갈 수 있는 곳 찾기`는 목적지 후보를 찾는 첫 단계다.

1. 서버가 출발지, 출발·복귀 일시, 자차, 관심사를 검증한다.
2. 서버가 TourAPI에서 지원 후보 지역의 관광지와 관심사 분류를 조회한다.
3. 서버가 출발 지역과 각 여행 지역 사이의 KTDB 자동차 일반 예상 이동시간을 조회한다. 계산 방법은 [거리 계산 방법](DISTANCE_CALCULATION.md)을 따른다.
4. 왕복 후 여러 관광지를 배치할 수 있는 1차 후보만 남긴다.
5. 서버가 1차 후보 지역에만 음식점·대표음식·운영 정보를 조회해 연결하고, 점심·저녁을 모두 구성할 수 있는 지역만 최종 후보로 남긴다.
6. 조회·계산한 데이터는 검색 스냅샷으로 묶는다. 사용자가 최종 후보를 고르면 새 외부 API를 호출하지 않고 해당 스냅샷으로 계획을 만든다.

음식점 조회는 모든 지원 지역이 아니라 관광지 조건을 통과한 1차 후보에만 수행한다. 브라우저는 외부 API를 직접 호출하거나 서비스 키를 받지 않는다. API 실패, 시간 초과, 형식 오류는 정적 데이터나 PoC 값으로 대체하지 않고 재시도 가능한 오류로 표시한다. 상세 호출 순서는 [MVP 데이터 조회 흐름](API_FETCH_FLOW.md), 음식 데이터 원천·선정 기준은 [대표음식·음식점 데이터 정책](FOOD_DATA_POLICY.md)을 따른다.

## 목적지 후보 추천

### 입력과 후보 데이터

- 입력: 출발지, 출발·복귀 일시, 이동수단(초기 MVP는 자차), 관심사
- 후보: TourAPI 데이터가 충분한 지원 지역과 KTDB 지역 매핑
- 필요 데이터: 출발 지역↔여행 지역 자동차 일반 예상시간, 관심사에 맞는 관광지, 점심·저녁 식사 후보

### 가능 여부와 정렬

후보마다 출발 지역과 여행 지역의 왕복 일반 예상시간을 계산한다. `복귀 시각 - 출발 시각 - 왕복 이동시간` 안에 1박 2일 계획을 구성할 수 있는 후보만 남긴다.

가능한 후보는 시간 적합성, 관심사 적합성, 여러 관광지를 배치할 수 있는 구성 가능성, 더 짧은 왕복 예상시간 순으로 평가한다. 관광지 내부 이동시간은 계산·선정·제약·표시에 쓰지 않는다. 동점은 더 많은 현지 시간, 안정적인 지역 식별자 순으로 정한다.

필요한 관광지 또는 점심·저녁 식사 후보가 부족하면 추천하지 않는다. 추천 카드에는 계획 생성에 필요한 관광지·음식점 데이터가 이미 연결돼 있어야 한다.

## 1박 2일 참고 계획 생성

### 시간 경계

- 1일차는 출발 시각부터 21:00 전까지, 2일차는 07:00부터 복귀 시각까지로 나눈다.
- 매일 21:00부터 다음날 07:00까지는 휴식으로 고정한다. 이 구간에는 관광·식사·이동을 배치하지 않는다.
- 1일차 출발 지역→여행 지역과 2일차 여행 지역→출발 지역의 시간만 KTDB 지역 간 일반 예상시간으로 반영한다.
- 관광지와 음식점은 각각 1시간을 차지한다. 여행지 내부 장소↔장소, 장소↔음식점 이동시간은 계산하거나 시간표에 표시하지 않는다.

### 관광지

- 사용자가 고른 관심 카테고리에 맞는 TourAPI 관광지를 추천한다.
- 같은 장소의 세부 지점이 중복으로 보일 경우 하나의 관광 방문으로 묶는다.
- 식사와 휴식 경계 밖의 남는 시간에 관광지를 배치한다. 체류시간은 모두 1시간으로 고정한다.

### 식사와 음식점

- 점심은 11:30~~13:30, 저녁은 17:30~~19:30 안에 각각 최소 1시간을 배치한다.
- 식사는 관심사와 무관하게 반드시 배치한다.
- 음식점은 지역 대표음식을 취급하고 해당 식사 시간에 운영 가능한 공공데이터 후보에서 고른다.
- 후보가 여럿이면 **공식 지정 여부**, 해당 식사와 연결된 관광지까지의 **직선거리**, 안정적인 장소 ID 순으로 고른다. 공식 지정 후보가 없으면 전체 후보에서 직선거리, 장소 ID 순으로 고른다. 직선거리는 음식점 하나를 일관되게 고르기 위한 동점 해소 기준이며, 이동시간·일정 제약·사용자 표시에는 쓰지 않는다.
- 평점·리뷰·랭킹은 사용하지 않는다.
- 대표음식 근거 또는 운영시간을 확인할 수 없으면 그 음식점을 추천하지 않는다.

### 결과와 예외

결과는 1일차·2일차별 관광·점심·저녁 시간표, 출발·복귀 일반 예상시간, 짧은 추천 이유, 조회 시각을 보여 준다. “방문 전 운영·휴무·예약 정보를 다시 확인하세요” 안내를 함께 표시한다.

관광지·점심·저녁·출발지↔여행지 시간이 부족해 최소 시간표를 만들 수 없으면 `지금은 계획을 만들 수 없어요`로 명확히 표시하고 다시 검색할 수 있게 한다. 외부 API 장애와 정상 응답이지만 조건을 채우지 못한 경우는 구분한다.
