# 거리 계산 방법

## 목적과 범위

출발 지역↔여행 지역은 KTDB 일반시간으로 계산한다. 서비스 2차 고도화부터 현지 연속 장소는 [직선거리 추정 정책](SERVICE_ENHANCEMENT_PHASE_2_PLAN.md)의 `straight-line-v1`으로 별도 시간을 확보한다. 30km/h·5분 올림·최소5분이며 동일 좌표는0분, 결측 연결은 미확정15분 예약이다. 지역 간 원천과 혼동하거나 실제 도로 시간이라고 표시하지 않는다.

지역 간 이동시간은 실시간 교통·내비게이션 시간이 아니다. 선택한 표준 출발 지역과 여행 지역 사이의 자동차 **일반 예상 이동시간**이며, 국가교통DB(KTDB) 2024 도로 네트워크의 252개 지역 존 중심 노드 간 승용차 기본 링크 비용으로 배치 산출한 여행 계획 참고용 추정치다. 시간대별 교통량·혼잡·사고·날씨는 반영하지 않는다.

## 지역 간 이동시간

1. 서버는 검증된 표준 출발 ID의 KTDB 존과 전국 여행 지역 존 사이에서 사전 산출·적재한 자동차 일반 예상시간을 사용한다. 기존 서울/부산 빠른 선택은 서울 중구/부산 중구 의미를 유지한다.
2. 존 중심 노드는 지역 기준점을 통일하기 위한 대표점이며, 관광지·청사·사용자의 상세 주소까지의 시간을 뜻하지 않는다.
3. 앱 서버는 적재된 지역 간 일반 예상시간만 조회한다. 사용자 검색 중 경로·지오코더·내비게이션 API를 호출하지 않는다.
4. 지원 지역 매핑 또는 일반 예상시간이 준비되지 않은 쌍은 추천 대상에서 제외하고, 임의의 시간으로 대체하지 않는다.

왕복 운전시간은 같은 편도 일반 예상시간의 두 배다. 이동 중 자유 식사 60분은 운전 분을 대신하지 않고 별도 경과시간으로 더한다. 사용자 출발·복귀는 시간표 경계로 반영하되 교통·사고·시간대별 혼잡 보정은 하지 않는다. 시간표와 후보 판정은 [2단계 공통 시간 엔진](MVP_PHASE_2.md)의 P2-01을 따른다.

지역 ID 매핑·적재·갱신과 OSRM 후속 대안은 [지역 간 일반 예상 이동시간 설정](INTERREGIONAL_TRAVEL_TIME.md)을 따른다.

지역 간 이동은 출발지·여행지 양방향 모두 야간에도 허용한다. 21:00~07:00 관광 휴식 규칙 때문에 운전을 다음날로 미루거나 야간 출발 입력을 거절하지 않는다. 시간대에 따라 KTDB 일반 예상시간을 보정하지 않는다.

## 검색 실행과 표시

`갈 수 있는 곳 찾기`를 클릭할 때 서버가 선택한 출발 지역권에서 전국 252개 지역권까지의 적재된 지역 간 일반 예상시간을 조회해 시간 적합 후보를 먼저 만든다. 결과는 그 검색 스냅샷에 보존하고 목적지 선택·일정 표시에서 재사용한다. 다음 검색도 같은 기준 데이터를 조회한다.

결과 화면에는 출발지→여행지 일반 예상시간과 조회 시각만 간결하게 표시한다. 실제 경로·실시간 교통으로 오해하게 하는 문구는 사용하지 않는다.

## 결측과 실패

필요한 지역 매핑 또는 일반 예상시간을 얻지 못하면 임의 시간으로 대체하지 않는다. 해당 목적지는 추천하지 않으며, 데이터 조회 장애와 정상 응답이지만 지원 값이 없는 경우를 구분해 재시도를 안내한다.
