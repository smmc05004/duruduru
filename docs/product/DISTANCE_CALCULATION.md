# 거리 계산 방법

## 원칙

거리와 이동시간은 사용자가 `갈 수 있는 곳 찾기`를 누를 때 계산한다. 미리 수집해 둔 도시·장소 간 고정값, 직선거리 환산값, PoC의 고정 30분은 사용하지 않는다.

여기서 말하는 값은 자동차 **도로 경로 거리**와 그 경로의 **일반 예상시간**이다. 실시간 교통·정밀 내비게이션·도착 시각 보장은 제공하지 않는다.

## 좌표 준비

경로 계산의 입력은 WGS84 경도·위도다.

1. 관광지와 음식점은 TourAPI가 제공하는 좌표를 우선 사용한다.
2. 좌표가 없는 장소는 주소를 서버의 승인된 지오코더로 변환한다. 주소 검색 서비스는 좌표를 얻는 단계일 뿐, 도로 경로나 이동시간을 계산하지 않는다.
3. 출발지는 사용자가 고른 주소 또는 지역을 같은 방식으로 좌표로 변환한다.
4. 좌표가 없거나 주소와 응답의 행정구역·장소명이 일치하지 않으면 해당 장소·경로를 사용하지 않는다.

주소·좌표·API 키는 브라우저에 노출하지 않는다.

## 도로 경로 계산

서버의 경로 어댑터는 두 좌표와 `car` 이동수단을 받아 다음 값을 반환한다.

- 방향이 있는 출발지와 도착지
- 도로 경로 거리(km)
- 일반 예상시간(분)
- 계산 시각과 제공자
- 성공·결측·오류 상태

도로망은 방향에 따라 달라질 수 있으므로 `A → B`와 `B → A`는 별도로 계산한다. 경로 제공자는 자동차 도로 경로를 좌표로 계산할 수 있어야 하며, 서비스 키는 서버 환경변수로만 관리한다. 공개 데모 서버를 서비스의 반복 호출 경로로 사용하지 않는다.

## 검색 실행에서 계산할 경로

한 검색 실행은 필요한 경로를 모두 서버에서 계산해 스냅샷에 저장한다.

1. 출발지 ↔ 각 목적지 대표 좌표: 목적지 가능 여부와 왕복 시간 계산
2. 선택 가능한 관광 권역 ↔ 관광 권역: 날짜별 방문 순서와 이동시간 계산
3. 관광 권역 ↔ 식사 후보: 점심·저녁 배치 판단
4. 마지막 방문 권역 ↔ 출발지: 복귀 가능 여부 계산

목적지 선택 뒤에는 이 스냅샷을 사용해 일정을 만들고 추가 외부 요청을 하지 않는다. 다음 검색은 새 TourAPI·지오코딩·경로 요청으로 새 스냅샷을 만든다.

## 결측과 실패

도로 경로를 얻지 못하면 직선거리, 임의 평균, 오래된 정적 데이터로 대체하지 않는다. 그 경로에 의존하는 목적지 또는 일정은 추천·생성 대상에서 제외하거나 `계획 생성 불가` 상태로 반환한다.

경로 제공자 오류와 좌표 결측은 구분해 기록한다. 사용자 화면에는 제공자 내부 오류나 키를 노출하지 않고, `이동시간을 계산하지 못했어요. 다시 시도해 주세요.`라고 안내한다.

## 사용자 표시

결과 화면에는 일반 예상 이동시간과 조회 시각만 간결하게 표시한다. 이는 실시간 교통 정보가 아니며 실제 운전 시간은 달라질 수 있음을 함께 안내한다. 제공자 세부 정보·원시 응답·좌표 정규화 과정은 기본 화면에 노출하지 않는다.
