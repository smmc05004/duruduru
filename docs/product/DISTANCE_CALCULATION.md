# 거리 계산 방법

## 목적과 범위

MVP는 출발지와 여행지 사이의 가용시간만 판정한다. 관광지 내부 장소↔장소, 장소↔음식점, 음식점↔다음 장소 이동은 계산·표시·일정 제약에 사용하지 않는다.

이동시간은 도로 경로·내비게이션·실시간 교통 시간이 아니다. 출발지와 여행지의 대표점 좌표 사이 **직선거리 기반 일반 예상시간**이며, 여행 계획 참고용 추정치다.

## 좌표 준비

1. 여행지 대표점은 행정 대표점 또는 TourAPI가 제공하는 WGS84 좌표를 사용한다.
2. 출발지 또는 필요한 대표점에 좌표가 없으면 승인된 서버 지오코더로 주소를 WGS84 좌표로 변환한다.
3. 주소→좌표 변환은 위치를 얻는 기능일 뿐 도로 거리나 자동차 이동시간을 반환하지 않는다.
4. 주소와 응답의 행정구역·장소명이 일치하지 않거나 좌표가 없으면 해당 여행지는 추천 대상에서 제외한다.

주소·좌표·API 키는 브라우저에 노출하지 않는다.

## 일반 예상시간 계산

서버는 출발지 대표점과 여행지 대표점의 위도·경도로 직선거리를 계산한다. 직선거리는 MVP에서 확정할 거리→일반시간 정책으로 분 단위 예상시간으로 변환한다.

- 계산 대상은 출발지↔여행지 대표점뿐이다.
- 왕복 시간은 같은 편도 일반 예상시간의 두 배로 계산한다.
- 도로망 방향, 실제 도로 거리, 교통·사고, 출발 시각은 반영하지 않는다.
- 이 정책의 거리 공식, 변환 계수, 반올림 규칙과 정책 버전은 구현 전에 한 문서에서 확정하고 검색 스냅샷에 보존한다.

## 검색 실행과 표시

`갈 수 있는 곳 찾기`를 클릭할 때 필요한 지오코딩과 직선거리 계산을 서버에서 수행한다. 결과는 그 검색 스냅샷에 보존하고 목적지 선택·일정 표시에서 재사용한다. 다음 검색은 새 좌표 조회와 계산을 수행한다.

결과 화면에는 출발지→여행지 일반 예상시간과 조회 시각, 직선거리 기반 추정이라는 사실만 간결하게 표시한다. 도로 경로·실시간 교통으로 오해하게 하는 문구는 사용하지 않는다.

## 결측과 실패

필요한 대표점 좌표를 얻지 못하면 직선거리나 임의 시간으로 대체하지 않는다. 해당 목적지는 추천하지 않으며, 지오코딩/API 장애와 정상 응답이지만 좌표가 없는 경우를 구분해 재시도를 안내한다.
