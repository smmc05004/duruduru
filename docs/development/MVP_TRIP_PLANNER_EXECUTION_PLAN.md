# MVP 여행 플래너 실행 계획

> 기준일: 2026-09-05 / 상태: 구현 진행

## 목표

입력 폼에서 자차·출발/복귀 일시·관심사를 받아 `갈 수 있는 곳 찾기` 한 번으로 최신 TourAPI 관광지와 음식점을 조회하고, KTDB 252존 일반 예상 이동시간을 적용한 목적지 후보와 선택 가능한 1박 2일 참고 계획을 만든다.

## 구현 순서

1. 서버 전용 검색 Route Handler를 만들고 TourAPI 키, 법정동 코드·관광지·음식점 조회를 브라우저에서 분리한다.
2. KTDB 테이블과 현재 지원 지역의 252존 매핑으로 왕복 가능 지역을 먼저 판정하고, 관심사 관광지가 여러 개인 지역만 1차 후보로 남긴다.
3. 같은 서버 요청에서 1차 후보에만 음식점 상세·메뉴·운영시간을 조회해 점심과 저녁 후보를 연결한다. 선택 이후 외부 API는 호출하지 않는다.
4. 선택 후보의 스냅샷으로 출발·복귀, 21:00~07:00 휴식, 점심·저녁, 관광지 1시간 블록을 배치하는 일정 엔진을 만든다. 내부 이동시간은 넣지 않는다.
5. 입력→후보→일정 UI를 서버 응답 계약으로 교체하고, 오류와 정상 결과 없음을 구분해 표시한다.

## 수용 기준

- KTDB 값이 없는 지역, TourAPI 장애, 관광지·식사 데이터 부족은 임의 값으로 대체하지 않는다.
- 최종 후보에는 관광지와 점심·저녁 음식점이 포함되며, 선택 단계의 새 API 요청은 없다.
- 1박 2일 기준에서 동일 유적의 하위 명소를 반복하지 않고 서로 다른 관광지를 여러 시간 블록에 배치한다.
- 실시간 교통·내비게이션·장소 내부 이동시간·유료 API·LLM은 추가하지 않는다.

## 검증

현재 MVP 작업 규칙에 따라 Jest, Playwright, 빌드, 수동 화면 점검, 별도 리뷰는 실행하지 않는다. 완료 전 변경 diff와 비밀정보 포함 여부만 확인한다.
