# MVP 여행 플래너 실행 계획

> 기준일: 2026-09-05 / 상태: 구현 진행

## 목표

입력 폼에서 자차·출발/복귀 일시·관심사를 받아 `갈 수 있는 곳 찾기` 한 번으로 정기 수집한 TourAPI 관광지 지역 프로필과 KTDB 252존 일반 예상 이동시간을 적용한 목적지 후보를 만든다. 사용자가 목적지를 선택하면 그 지역의 최신 TourAPI 음식점 목록만 조회해 1박 2일 참고 계획을 만든다.

## 구현 순서

1. 서버 전용 검색 Route Handler를 만들고, 일일 TourAPI 관광지 지역 프로필·법정동 매핑·KTDB 시간 테이블 조회를 브라우저에서 분리한다.
2. KTDB 테이블과 전국 252존 매핑으로 왕복 가능 지역을 먼저 판정하고, 관심사 관광지 근거가 여러 개인 지역만 최종 후보로 남긴다. 검색 중 음식점 API는 호출하지 않는다.
3. 지역N문화 원본에서 향토음식 문화 키워드만 정규화하고, 모범음식점 API를 수집해 인증 캐시를 만든다. 지역N문화 관련 음식점 필드는 쓰지 않으며, 인증은 TourAPI 목록과 전화번호 또는 정규화 상호·주소가 일치할 때만 적용한다.
4. 목적지 선택용 서버 Route Handler를 만들고, 선택 지역 한 곳의 음식점 목록 기본 정보만 제한 동시성·페이지네이션으로 조회한다. 음식점 상세·메뉴·운영시간은 조회하지 않는다.
5. 선택 지역의 관광지 프로필과 음식점 목록으로 출발·복귀, 21:00~07:00 휴식, 점심·저녁, 관광지 1시간 블록을 배치하는 일정 엔진을 만든다. 내부 이동시간은 넣지 않는다.
6. 입력→후보→선택 지역의 식당 목록 수집 상태→일정 UI를 서버 응답 계약으로 교체하고, 오류와 정상 결과 없음을 구분해 표시한다.

## 수용 기준

- KTDB 값이 없는 지역, TourAPI 장애, 관광지·식사 데이터 부족은 임의 값으로 대체하지 않는다.
- 최종 후보는 관광지 관심사 근거와 시간 정보로 구성하며 음식점은 포함하지 않는다. 선택 단계에서 선택 지역 한 곳의 음식점 목록만 새 API 요청으로 가져온다.
- 1박 2일 기준에서 동일 유적의 하위 명소를 반복하지 않고 서로 다른 관광지를 여러 시간 블록에 배치한다.
- 실시간 교통·내비게이션·장소 내부 이동시간·유료 API·LLM은 추가하지 않는다.

## 검증

현재 MVP 작업 규칙에 따라 Jest, Playwright, 빌드, 수동 화면 점검, 별도 리뷰는 실행하지 않는다. 완료 전 변경 diff와 비밀정보 포함 여부만 확인한다.
