# 정적 도로 경로·좌표 수집 매니페스트

## 상태와 원칙

2026-09-03 기준 초기 3×3과 참고 계획 표시 순서에 필요한 장소 쌍은 OSRM 공개 데모 서버의 소량 수동 조회로 수집해 `static-travel-time-data.ts`에 넣었다. 이 문서는 `DECISIONS.md` 10절의 실행 절차다. 서비스 런타임에는 경로 API, 지오코딩 API, 지도 UI, 실시간 교통을 연결하지 않는다.

정적 값은 내비게이션이나 분 단위 도착을 보증하지 않는 자동차 도로 경로 기반 **일반 예상시간**이다. PoC의 고정 30분, 직선거리 환산, 출처 없는 평균은 어떤 결측에도 사용하지 않는다.

## 수집 범위

| 단계 | 대상                                                            | 완료 기준                                                         |
| ---- | --------------------------------------------------------------- | ----------------------------------------------------------------- |
| 1    | 서울특별시·대전광역시·부산광역시 대표점 → 경주·공주·강릉 대표점 | 완료 — 방향성 있는 3×3 편도 도로 경로 레코드                      |
| 2    | 결과에 실제 선택되는 각 목적지의 정규화 완료 장소 ↔ 장소        | 완료 — 초기 표시 순서에 필요한 방향성 있는 3개 쌍만 기록          |
| 3    | 정규화 완료 장소 ↔ 대표음식 음식점                              | 대표음식·음식점 근거가 확인된 경우에 필요한 방향성 있는 쌍만 기록 |

모든 가능한 POI 조합을 미리 전수 수집하지 않는다. 도로망에 따라 방향별 거리·시간이 달라질 수 있으므로 `A → B`와 `B → A`는 별도 레코드다.

### 초기 수집 배치

- 배치: `osrm-manual-2026-09-03`
- 경로 엔진·도로 데이터: OSRM 공개 데모 서버의 car profile / OpenStreetMap
- 이용 조건 확인: [OSRM 공개 데모 사용 정책](https://map.project-osrm.org/about.html)을 2026-09-03에 확인했다. 요청 템플릿과 각 끝점 좌표·옵션은 레코드 `reproductionId`에 보존한다.
- 범위: 3×3 도시 기준점 9건과 경주 불국사→첨성대, 공산성 광복루→쌍수정, 강릉 굴산사지→경포대 3건
- 방식: 런타임·대량 배치가 아닌 1초 이상 간격의 소량 수동 조회. 원시 응답은 저장하지 않고 거리·시간·좌표 provenance·재현 식별자만 보존한다.
- 표시: 결과 화면은 추정 상태, 출처와 기준일을 유지하고 실시간 교통이 아님을 고지한다.

## 좌표 정규화 절차

1. TourAPI 또는 다른 승인 원천이 제공한 WGS84 좌표가 있으면 그대로 사용한다. 원천 ID, 좌표, 제공자, 수집일·데이터 버전을 보존한다.
2. 주소만 있는 장소·음식점은 허용된 주소→좌표 제공자(초기 후보: 카카오 Local)로 **사전 수집 시에만** 조회한다. 주소·질의, 선택한 응답의 정규화 주소·WGS84 좌표, 제공자, 수집일, 매칭 근거를 보존한다.
3. 동일성은 원천 ID·상호명·행정구역·도로명/지번 주소의 일치로 확인한다. 복수 후보 중 단일 정확 일치를 입증할 수 없으면 자동 선택하지 않는다.
4. 빈 주소, 좌표 없는 응답, 행정구역 불일치, 모호한 다중 결과는 `missing`으로 기록한다. 장소명 검색, 지도 UI 자동화, 사람이 감으로 좌표를 옮기는 보정은 금지한다.

사용자 자유 입력 주소는 F-01 범위 밖이다. 수집 대상은 공개 소스의 장소·음식점과 이미 승인된 도시 대표점뿐이며, API 키·비밀값은 어떤 기록에도 남기지 않는다.

## 도로 경로 수집 절차

1. 두 끝점이 모두 WGS84 좌표로 정규화됐는지와 차량 모드 사용 가능 여부를 검증한다.
2. 제공자·데이터셋의 이용 약관에서 호출 한도, 사전 저장, 제품 내 표시·재배포, 원시 응답 보관 조건을 수집 배치 기록에 남긴다.
3. 허용된 엔진에 `경도,위도;경도,위도`의 자동차 경로 요청을 한 번 수행하고 거리(km)와 일반 예상시간(hours)을 기록한다. 초기 검토 후보는 OSM 도로망 기반 OSRM이다.
4. 제공자 요청 식별자 또는 서비스키 없이 다시 찾을 수 있는 요청 요약·응답 해시를 `reproductionId`로 남긴다. 좌표 입력, 엔진/데이터셋, 차량 모드, 수집일, 데이터·정책 버전도 연결한다.
5. 값은 검증 후 정적 매니페스트에만 반영한다. 앱은 그 정적 값을 조회할 뿐 외부 요청을 하지 않는다.

공개 OSRM 서버는 소량의 수동 검증 외에 대량·반복 수집에 쓰지 않는다. 호출량 또는 저장·표시 허가가 불명확하면 배치를 중단한다. 그 경우 허용된 상용/공공 제공자, 승인된 데이터 내보내기 또는 자체 운영 엔진을 새 결정으로 선택하기 전에는 숫자를 넣지 않는다.

## 레코드 입력 조건

`static-travel-time-data.ts`의 정적 레코드는 아래 모든 항목이 있을 때만 추가한다.

| 필드        | 요구사항                                                                              |
| ----------- | ------------------------------------------------------------------------------------- |
| 끝점        | 안정 ID, WGS84 좌표와 그 원천/정규화 provenance, 방향                                 |
| 거리·시간   | 자동차 도로 경로 거리(km)와 일반 예상시간(hours)을 함께 기록. 0·음수·임의 기본값 금지 |
| 상태        | 실시간값이 아닌 `estimate`                                                            |
| 출처        | 경로 제공자/도로 데이터셋, 좌표 원천 또는 지오코더, 수집 배치의 이용 조건 확인        |
| 기준일·버전 | 조회·내보내기 기준일(`YYYY-MM-DD`), 데이터·정책 버전                                  |
| 재현 식별자 | 비밀값 없이 같은 끝점·모드·제공자·배치를 추적하는 ID 또는 요청 요약/응답 해시         |

원시 응답의 저장·표시가 허용되지 않으면 허용 범위의 메타데이터와 해시만 남긴다. 라이선스·출처 표기가 필요하면 결과 UI와 데이터 문서에 함께 반영할 수 있는지 먼저 확인한다.

## 결측과 사용자 표시

- 좌표 또는 도로 경로가 없으면 `null`/`missing`으로 남긴다. 추천·참고 계획은 이를 임의 시간이나 후보 0개로 바꾸지 않는다.
- 사용자에게는 “일반 예상 이동시간(사전 수집 도로 경로 기준)”, 출처·기준일·추정 상태와 “실시간 교통이 아님”을 표시한다.
- 결측 구간은 “이동시간 정보 없음”과 최신 정보 확인 행동으로 표시한다. 도로 경로 값이 없다는 사실을 직선거리 근사로 숨기지 않는다.
