> 상태 기준일: 2026-09-01 / 기준 커밋: `e817653` (`main`)
>
> 이 문서는 다음 employee 작업을 재개하는 **실행 현황의 단일 진입점**이다. 제품 요구사항과 결정의 단일 출처는 각각 `docs/product/PRD.md`, `docs/product/DECISIONS.md`, `docs/product/FUNCTIONAL_SPEC.md`이며, 이 문서는 그것을 바꾸지 않는다.

## 1. 사용하는 방법과 상태 규칙

작업을 시작할 때는 이 문서에서 `다음`인 에픽 한 개를 선택하고, 연결된 기능 ID·선행 조건·수용 기준을 읽는다. 상태의 뜻은 다음과 같다.

| 상태 | 뜻 |
| --- | --- |
| 완료 | 기능 명세의 현재 수용 기준을 실제 데이터 계약으로 충족했고, 코드·테스트 근거가 있다. |
| 부분 완료 (목업) | 화면 또는 규칙은 동작하지만 PoC/임시 데이터 또는 미확정 정책에 의존한다. **정식 MVP 완료가 아니다.** |
| 부분 완료 (조사) | 조사 결과나 작업 준비는 남았지만 구현 완료 조건을 만족하지 않는다. |
| 다음 | 현재 선행 조건으로 바로 시작할 employee 작업이다. |
| 대기/차단 | 제품 결정 또는 앞 에픽 산출물이 없어 구현을 시작할 수 없다. |
| 미착수 | 관련 구현·조사 근거가 없다. |

`완료`와 `부분 완료 (목업)`을 혼동하지 않는다. 특히 `lib/mock-data.ts`의 값, PoC 화면, 고정 이동시간은 제품 정책이나 정식 데이터가 아니다.

## 4. 다음 employee 작업: E1 도메인 계약·목업 분리

**목표:** PoC 목업을 정식 데이터나 정책으로 승격하지 않은 채, 이후 E2 조사 결과와 E3~E7 구현이 같은 타입·상태 모델을 사용하도록 데이터 계약과 목업 어댑터를 완성한다.

**범위:** `docs/product/FUNCTIONAL_SPEC.md` 5장의 계약을 코드 경계로 옮긴다. 최소한 목적지·장소·운영 정보·체류시간·출발지↔목적지 이동·장소 간 이동·축제·대표음식·음식점에 대해 안정 식별자, 출처, 수집/갱신 시각, `정상/추정/fallback/결측/오래됨` 상태를 전달할 수 있어야 한다. 정책은 주입 가능한 별도 경계로 유지한다.

**완료 조건:**

- 화면과 추천/일정 엔진이 `lib/mock-data.ts`의 원시 구조를 직접 읽지 않는다.
- 목업은 계약을 구현한 명시적 어댑터이며, 모든 임시값은 출처·기준 시각·임시 상태를 보존한다.
- 결측은 임의 기본값으로 바뀌지 않고 계약의 상태로 표현된다.
- 계약과 어댑터를 검증하는 Jest 테스트가 있으며, 기존 F-01~F-03 회귀와 화면 흐름을 확인한다.
- 기능 구현이므로 `context → plan → implement → verify → review → handoff` 사이클을 전부 기록하고 독립 reviewer 검토를 받는다.

**범위 밖:** 초기 지원 지역·이동수단·출발지 단위의 값 확정, 실제 API/DB 도입, 음식명 목록 확정, 운영시간 파싱, 일정 알고리즘 구현. 이들은 결정 또는 후속 에픽의 일이다.

## 5. E1 이후의 고정 순서

1. E1을 완료한다.
2. E2에서 계약을 사용해 데이터 품질 조사·수집 경계를 보강한다. 음식 데이터의 세부 순서는 `docs/product/FOOD_DATA_NEXT_STEPS.md` 2절을 따른다.
3. E3의 입력을 정식 지원 조건 계약에 연결하고 F-01 수용 기준을 완료한다.
4. E4·E5를 정식 데이터 계약과 신뢰도 상태에 연결해 F-02·F-03·F-05를 완료한다.
5. E6·E7은 필요한 제품 결정이 기록된 뒤에만 시작한다.
6. E8·E9는 P0 흐름과 그 결과 모델이 안정된 뒤에 진행한다.

이 순서는 제품 우선순위가 아니라 의존성 순서다. 새 제품 결정이 이 순서를 바꾸면 먼저 `docs/product/DECISIONS.md`와 이 문서의 상태·차단 사유를 함께 갱신한다.

## 6. 매 작업 후 갱신 규칙

employee는 작업 완료 보고·커밋·PR 준비 전에 다음을 수행한다.

1. 관련 기능 ID와 에픽의 상태를 실제 수용 기준으로 다시 판정한다. 목업 또는 미확정 정책 의존이 남으면 `완료`로 올리지 않는다.
2. 이 문서에 커밋 해시, 코드 경로, 실행한 Jest/Playwright/`npm run verify` 결과를 완료 근거로 남긴다. 실행하지 못한 검증은 이유와 위험을 함께 남긴다.
3. 완료 조건이 남으면 구체 항목을 `선행 조건·차단 사유`에 유지한다. 제품 판단이 필요하면 값을 정하지 말고 PM이 `DECISIONS.md`에 기록하도록 요청한다.
4. 하나의 에픽이 완료되면 상태를 바꾸고, 의존성상 가장 앞선 미완료 에픽 하나만 `다음`으로 표시한다.
5. 문서 변경만이면 위험에 비례한 검증을 실행한다. 기능·화면 구현이면 `docs/agent/WORK_CYCLE.md`의 전체 사이클과 독립 리뷰를 반드시 적용한다.
