## 작업 경계

employee 구현리드는 계획·공용 계약·시간/선정/편집 엔진·서버검색을 맡는다. root가 별도 담당에게 음식점/상세 API와 UI/저장소를 배정한다. 파일 담당은 중첩하지 않는다. 기존 `mvp-core`는 이전 호출자 호환성을 유지하고 새 UI는 데이터 없는 계약과 새 순수엔진만 가져온다. 핵심 계약을 먼저 파일로 확정한 후 UI/API 구현을 연결한다.

## 확인·위험 기록

시간 조합은 같은 검색의 일시·편도 분별 요청 내 메모를 사용하며 관광 선정은 후보의 일별 방문 수 조합별 재사용한다. 공용 타입/그룹/시간 모듈에는 전국 JSON을 가져오지 않는다. 관광 사진은 프로필에 이용허락 코드가 없어 보수적으로 빈 이미지로 보내며 클릭 상세 담당이 허락 근거를 확인해 제공한다. 관광 수정 후 이미 배정된 식당이 이동 중 식사로 바뀌어 사라지지 않도록 해당 끼니의 현지식사 경계를 보존하고 불가하면 원래 계획을 유지한다.

사용자 지시에 따라 테스트 작성/실행, lint, typecheck, build, 브라우저 자동점검, 독립 리뷰와 작업 사이클을 실행하지 않는다. 포맷팅만 허용한다. 수용 조건은 구현과 사용자의 직접 화면 확인 기준이다. API 키 미설정/외부 목록·상세 결측은 실제 실패 상태로 표시하며 관광 시간표를 취소하지 않는다. KTDB 값과 좌표 근접성을 시간으로 혼합하지 않는다. 결과는 참고 계획이며 영업·교통 보증이 아니다.

## 다음 작업과 사용자 확인

P2-01~07 코드 반영은 완료했다. 다음 단계는 PR에서 사용자가 직접 기능을 확인하는 것이다. 실행 검증을 통과했다는 의미는 아니다. 기존 저장소 CI는 수정하지 않았으며 PR 생성에 따라 자동 실행될 수 있다.

- 서울/부산·관심사로 검색하고 출발 권역 제외·최대 3곳의 실제 초안을 확인한다.
- 08:00 출발·다음날 20:00 복귀에서 이동 중 식사와 운전 분이 분리되고 휴식·현지 여유가 표시되는지 확인한다.
- 관광지 고정·교체·시간 변경·삭제와 식당 교체 후 다른 선택 보존을 확인한다.
- 기기 저장·새로고침 후 복원·저장 후 변경·선택 삭제를 확인한다.
- 음식점 목록 실패/부분 성공 재시도와 관광지·음식점 클릭 상세를 확인한다.

현 환경에서 실제 TourAPI 추가 호출은 수행하지 않았다. 신규 관광 상세 필드의 충족률·실제 응답과 무료 API 한도는 사용자 확인 시 관찰할 사항이다. 관광 사진은 명시적 이용허락 근거가 있을 때만 표시한다. 공공데이터 원본 재수집·갱신 자동화, 유료 API, 정밀 이동시간, 숙소·축제·날씨는 이번 구현에서 추가하지 않았다.
