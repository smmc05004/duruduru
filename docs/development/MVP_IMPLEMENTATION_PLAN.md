# MVP 구현 계획

> 상태: 사용자 검토용 초안 / 기준일: 2026-09-05
>
> 이 문서는 현재 MVP 기능을 구현하기 위한 순서와 완료 조건을 정리한다. 코드리뷰, 작업 사이클, 자동 테스트·빌드·화면 점검 절차는 이 계획의 범위에서 제외한다.

## 1. 구현 목표와 고정 범위

완료 목표는 사용자가 KTDB 252개 지역권에 대응하는 시·군·구명 출발지를 선택 또는 검색하고, 자차·출발/복귀 일시·관심사를 입력해 `갈 수 있는 곳 찾기`를 누르면 전국 목적지 후보 중 최종 3곳을 받고, 하나를 선택해 1박 2일(1일차 08:00 출발, 2일차 20:00 복귀) 날짜별 계획을 보는 것이다. 경주·공주·강릉은 초기 예시·검증 지역이며 지원 목적지의 전부가 아니다.

고정 규칙은 다음과 같다.

- 후보 검색은 `갈 수 있는 곳 찾기` 클릭에서 서버가 실행한다. 출발 지역권에서 전국 252존의 왕복 일반 예상시간으로 시간 적합 후보를 먼저 좁힌 뒤, 그 후보에만 관광지·음식점 목록 기본 정보와 대표음식 근거를 제한 동시성·페이지네이션으로 연결하며, 사용자가 선택할 때는 새 외부 API를 호출하지 않는다.
- 이동시간은 국가교통DB(KTDB) 2024 도로 네트워크에서 252존 중심 노드 간 승용차 기본 링크 비용으로 사전 산출한 일반 예상시간만 사용한다. 실시간·시간대별 혼잡·내비게이션 시간은 쓰지 않으며, 사용자 검색 중 경로 API를 호출하지 않는다.
- 관광지↔관광지와 관광지↔음식점의 이동시간은 계산·표시·선정·제약에 쓰지 않는다.
- 관광지와 음식점 체류시간은 각각 1시간이다.
- 매일 21:00~다음날 07:00은 휴식이며 관광·식사 배치를 금지한다.
- 점심(11:30~~13:30)과 저녁(17:30~~19:30)은 반드시 한 시간씩 배치한다. 음식점은 공공 데이터의 대표음식 근거 또는 기본 목록 정보를 사용하며, 실제 운영시간·메뉴는 사용자가 상세를 열 때 확인한다.
- 엔진은 규칙 기반이고 LLM, 평점·리뷰·랭킹, 도로 경로 API, 실시간 교통, 내비게이션은 사용하지 않는다.

## 3. 현재 정적 구현의 교체·삭제 대상

다음은 새 MVP의 데이터 원천이나 계산 근거로 더 이상 사용하지 않는다.

- `lib/static-travel-time-data.ts`의 OSRM 청사 3×3 값과 관광지·음식점 내부 경로 매니페스트
- `lib/route-collection.ts` 및 OSRM/OSM 수동 수집 provenance
- `lib/reference-itinerary-data.ts`의 최소 장소 앵커와 장소 간 경로값
- `lib/recommendation-data-adapter.ts`가 정적 데이터만 읽어 후보를 만드는 경로
- `lib/support-conditions.ts`의 고정 3개 출발지·목적지 지원 목록과 이를 전제한 입력 UI·테스트 fixture
- `lib/reference-itinerary.ts`·`lib/planner.ts`의 장소 간 이동시간, 방문시간 결측 카드, 식사 직접 확인 fallback
- 결과 화면의 OSRM·정적 경로·내부 장소 이동 근거 표시

KTDB 지역 간 자동차 시간으로 전국 252개 지역권을 후보 판정한 뒤, OSRM 청사 3×3 값·내부 경로 정적 데이터와 수집 코드는 삭제한다. 현재 코드의 고정 3개 출발지·목적지 구현은 문서 기준선과 불일치하므로 전국 KTDB 존·TourAPI 법정동 매핑으로 교체한다. PoC 고정 이동시간, 장소 간 고정 30분, 정적 음식점 fallback은 새 구현에 이관하지 않는다.

## 4. API와 환경변수 의존성

| 의존성                           | 용도                                                 | 호출 시점                                           | 환경변수/조건                                                                                 |
| -------------------------------- | ---------------------------------------------------- | --------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| TourAPI KorService2              | 최신 관광지·상세·관심사 분류                         | `갈 수 있는 곳 찾기` 클릭                           | `TOUR_API_SERVICE_KEY`; 서버 전용                                                             |
| TourAPI KorService2              | 시간 적합 후보 지역의 최신 음식점 목록 기본 정보     | KTDB 시간 적합 후보를 좁힌 뒤 같은 검색 요청 안에서 | `TOUR_API_SERVICE_KEY`; 서버 전용                                                             |
| TourAPI KorService2 detailIntro2 | 사용자가 연 음식점의 메뉴·운영시간·휴무 상세         | 음식점 클릭                                         | `TOUR_API_SERVICE_KEY`; 서버 전용                                                             |
| 국가교통DB(KTDB)                 | 출발 지역↔여행 지역 자동차 일반 예상시간             | 개발 데이터 적재 시, 검색에서는 저장값 조회         | 수단·자료 연도·지역(교통존) 매핑을 보존하며, 런타임 경로 API를 쓰지 않는다                    |
| 대표음식·음식점 공공 데이터      | 시간 적합 후보 지역 음식점의 대표음식·공식 지정 근거 | KTDB 시간 적합 후보를 좁힌 뒤 같은 검색 요청 안에서 | 지역N문화 공식 다운로드, TourAPI, 모범음식점 표준데이터를 `FOOD_DATA_POLICY.md` 규칙대로 결합 |

TourAPI 키는 현재 개발 환경에 존재한다. 대표음식 데이터 접근에 필요한 키·다운로드 경로가 확정되지 않았다면, 그 항목을 임의 데이터나 상용 지도 UI 스크래핑으로 대체하지 않는다.

## 5. 최종 완료 조건

다음이 모두 성립하면 MVP 핵심 흐름 구현을 완료로 판단한다.

1. 검색 클릭 한 번으로 출발 지역권에서 전국 252개 지역권까지의 KTDB 시간 필터와 후보 검색 스냅샷 생성이 시작된다.
2. 252존에 대응하는 시·군·구명 출발지 선택 또는 검색과 TourAPI 법정동 코드 매핑이 동작한다.
3. 시간 적합 후보에만 최신 관광지·음식점 목록 기본 정보·대표음식 근거를 제한 동시성·페이지네이션으로 조회해 점심·저녁을 구성하고, 최종 3곳을 보여 준다.
4. 1일차 08:00 출발·21:00 휴식 시작, 2일차 07:00 재개·20:00 복귀의 날짜별 시간표가 생성된다.
5. 관광지·음식점은 1시간씩만 배치되고, 내부 이동시간·도로 경로·실시간 교통 정보는 어디에도 쓰거나 표시하지 않는다.
6. 음식점 상세는 사용자가 클릭할 때만 서버에서 조회하며, 운영시간·메뉴·휴무 결측 또는 상세 실패는 일정 후보를 소급 제외하지 않고 해당 음식점의 확인 필요/재시도 상태로 보인다.
7. 데이터/API 부족은 정직한 재시도 또는 계획 생성 불가 상태로 보이며, 오래된 정적 값·PoC 값·임의 fallback으로 대체되지 않는다.
