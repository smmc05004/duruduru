# DURUDURU (두루두루) PoC

목적지를 먼저 정하지 않아도 되는 국내 여행 계획 추천 서비스의 프로토타입입니다. 출발지·여행 시간·이동 수단·관심사를 입력하면, 갈 수 있는 지역을 우선 추천하고 선택한 지역의 간단한 관광 일정까지 만들어 줍니다.

## 실행

```bash
npm install
npm run dev
```

브라우저에서 `http://localhost:3000`을 엽니다.

검증 명령은 다음과 같습니다.

```bash
npm run lint
npm run build
```

## 현재 구현 범위

- 서울 출발 기준 경주·공주·강릉의 추천 점수 계산
- 역사/자연/문화/미식 관심사에 따른 후보 우선순위
- 자차·대중교통 평균 예상 이동시간과 여행 가능 시간 반영
- 관광지 운영시간, 월요일 휴관 예시, 권장 체류시간을 반영한 일정
- 여행 기간과 겹치는 지역 축제의 일정 내 제안
- 지역 대표 음식(경주식 한정식, 공주 밤, 초당순두부 등) 표시

## 목업 데이터 구조

`lib/mock-data.ts`에 목적지별 평균 이동시간, 태그, 관광지 운영시간/휴관일/권장 체류시간, 축제, 대표 음식을 넣었습니다. `lib/planner.ts`는 데이터 공급원과 독립적으로 추천과 일정 생성만 담당합니다.

## 실제 공공 API로 교체할 지점

PoC 다음 단계에서는 `lib/mock-data.ts`를 서버 측 공급자 계층으로 바꾸면 됩니다.

- **관광지·운영시간·축제**: 한국관광공사 TourAPI의 지역기반/소개정보/행사정보
- **평균 이동시간**: 한국도로공사 또는 경로 서비스의 시간대별 평균 소요시간
- **음식**: 지자체 공개데이터의 지역 음식점·대표음식 정보
- **체류시간**: 관광지별 제공 데이터가 있으면 우선 적용하고, 없으면 카테고리별 기본 체류시간 적용

API 응답은 서버 Route Handler에서 날짜 단위로 캐시하고, UI에는 정규화한 `Destination` 형태만 전달하는 구조를 권장합니다. 이 프로젝트는 DB 없이 시작했으며, 이후 Redis나 Next.js 데이터 캐시로 교체할 수 있습니다.

## TourAPI 실데이터 검증 (가장 먼저 할 일)

1. 공공데이터포털에서 [한국관광공사 국문 관광정보 서비스_GW](https://www.data.go.kr/tcs/dss/selectApiDataDetailView.do?publicDataPk=15101578)를 활용신청하고 **Decoding 서비스키**를 발급받습니다.
2. `.env.local.example`을 `.env.local`로 복사한 후 키를 넣습니다. `.env.local`은 커밋하지 않습니다.
3. 아래 명령을 실행합니다.

```bash
npm run check:tour-api
```

이 검증은 경주·공주·강릉의 실제 관광지와 문화시설 목록을 가져오고, 각 지역에서 최대 5개 장소의 주소·좌표·운영시간·휴무일 필드 충족 여부와 현재 이후 축제 데이터를 표로 보여줍니다. TourAPI v4.4의 법정동 코드(`lDongRegnCd`, `lDongSignguCd`)를 사용합니다. 결과의 운영 정보 충족률이 낮으면, 일정 생성에는 TourAPI의 값 우선 → 지자체/관광지 개별 데이터 보완 → 카테고리별 기본값 순의 fallback이 필요하다는 근거가 됩니다.
